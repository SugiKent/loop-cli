## MODIFIED Requirements

### Requirement: Model は Card をタブ別に並べ、選択行を 1 つ持つ
`internal/ui` は Bubble Tea の Model として型 `Model` と、取得関数・`gh` クライアント・エディタ起動・起動時の選択肢を受け取る `New(fetcher Fetcher, client gh.GHClient, editor Editor, opts Options) Model` を MUST 提供する。`Fetcher` は `func(ctx context.Context) (*fetch.Result, error)` で、s07 の `fetch.Fetch` を `client` と `repos` で閉じ、s13 `snapshot-cache`「取得が成功するたびにスナップショットを保存する」の保存で包んだものを `cmd/loop-cli` が渡す。`client` は書き込み（s10 `answer-question` の `a`。後続の `t` / `m` / `n` / `s` も同じ `client` を使う）に使い、取得には使わない。`Editor` は s10 `answer-question`「a は画面の対象を決めて回答テンプレートを入れたエディタを開く」の型で、`cmd/loop-cli` は `ExternalEditor(Config.Editor)` を、テストは固定文字列を返すスタブを渡す。`Options` は公開する構造体で、次の 5 つのフィールドを持ち、ゼロ値は「スナップショット無し・自動更新無し・通知無し・更新の確認無し・merge 方式は既定」である（s13 が導入。テストは `Options{}` を渡してよい）。
- `Snapshot *snapshot.Snapshot`: `Model` が起動時の stale 表示に使う Card 群と保存時刻を持つ。`nil` なら `Model` は空の画面から始める（s13 `snapshot-cache`「起動時にスナップショットがあれば stale 表示から始める」）
- `RefreshInterval time.Duration`: 自動更新の間隔。0 なら自動更新しない（s13 `auto-refresh`）
- `Notify Notifier`: デスクトップ通知の関数。`nil` なら通知しない（s13 `desktop-notify`）
- `CheckUpdate UpdateChecker`: 起動時に 1 度だけ新しい版があるかを調べる関数。`nil` なら調べない（s23 `self-update`）
- `MergeMethods map[string]string`: リポジトリ名から merge 方式を引く対応表。`nil` または該当が無ければ `squash` を使う（s14 `merge-pr`「merge 方式はリポジトリ名から引く」）
`Model` は `classify` を呼ばず、`fetch.Result.Cards` の `Card.Result` をそのまま使う。
`Model` は保持中の `Cards` を `Card.Result.Tab` で mvp.md の 4 タブ（`model.TabNow` / `TabBacklog` / `TabInProgress` / `TabAbnormal`）に振り分け、1 枚の Card を 1 行にする。Card は必ずどれか 1 つのタブに入る（s05 の `classify.Card` は `Card.Result.Tab` を空にしない）。

今やる / バックログ / 異常のタブ内の並びは第 1 キー `Card.Result.Priority` 昇順、第 2 キー行の主体の `UpdatedAt` 降順（新しいものが上）、第 3 キー主体の `Repo` 昇順、第 4 キー主体の番号昇順とする（第 1 キーは s05 が定め、第 2 キー以降は design.md の未決事項で定めた既定値）。

進行中タブのタブ内の並びは第 1 キー主体の `Repo` 昇順、第 2 キー主体の段階順、第 3 キー主体の `UpdatedAt` 降順、第 4 キー主体の番号昇順と MUST する。段階順は Requirement「進行中タブの種別の列は段階ラベル名を出す」が定める順で、段階を持たない行は同じ段階の行より後に置く。進行中タブでは優先度を並びのキーから外す。このタブに入る局面は `in-progress` だけで `Priority` が全行同じなので、優先度をキーに残しても並びが決まらないためである。

`Model` は現在のタブ（初期値は今やる）と、画面全体で 1 つの選択行の添字（初期値 0）を持つ。選択行の添字をタブごとに持たないのは、タブ切替のたびに先頭を見る mvp.md の「先頭から捌く」体験に合わせるためである。選択行の添字は常に `0 ≤ 添字 < そのタブの行数` に収め、行数 0 のタブでは選択行が無い。タブ切替と `Cards` の差し替えで行数が減ったら添字を末尾に丸める。

### Requirement: 表の行は優先記号・種別・リポジトリ・番号・タイトル・経過を種別の色で出す
`Model` の `View` は現在のタブの各行を、mvp.md の列順 優先 / 種別 / リポジトリ / # / タイトル / 経過 で MUST 描く。各列の表記は次のとおりで、`internal/ui` は 1 枚の Card 分の行を返す関数を持つ（タイトルの折り返しにより 1 枚が 2 行以上になることがある。列幅は design.md の未決事項の既定値）。

- 番号: 主体が Issue なら `#<n>`、PR なら `PR<n>`（s06 の `classify` サブコマンドと同じ表記）
- タイトル: 主体の `Title`。列幅は端末幅から他の列の合計 48 を引いた残り。**列幅に収まらなければ列幅で折り返し、`Title` を全文出す**（#2）。折り返して生まれた継続行は、タイトル列の開始位置（先頭から 43 列）まで空白を置いてからタイトルの続きを書き、経過の列には何も書かない。これにより継続行はタイトルの開始位置に縦が揃う。幅の判定と折り返し位置は表示幅（`ansi.StringWidth` が返す値）で決め、全角文字と絵文字を含むタイトルでも桁がずれない。折り返し位置にあった空白 1 個は改行に置き換わって消える（`ansi.Wrap` の仕様。design.md D1）。列幅が 2 列未満なら（端末幅が 49 以下。タイトル列に全角 1 文字が入らない幅）タイトルを出さず、行は端末幅で切る

## ADDED Requirements

### Requirement: 進行中タブの種別の列は段階ラベル名を出す
進行中タブの表では、種別の列に `Card.Result.Situation.Kind()`（このタブでは常に `進行中`）の代わりに、その行の主体の**段階ラベル名**を MUST 出す。段階ラベルは主体が Issue なら issue の段階ラベル、主体が PR なら PR の段階ラベルで、そのリポジトリの運用方式（Requirement「運用方式は取得のたびに判定した結果を持つ」の表。分からないリポジトリはゼロ値の `sdd`）で語彙が決まる。

表記は次のとおりとする。`sdd` 方式の issue の段階ラベルからは `stage:` の接頭辞を落とす（列幅 10 に収めるため。段階ラベルであることは列の位置が示す）。

| 方式 | 主体 | 段階ラベル | 列に出す語 |
| --- | --- | --- | --- |
| `sdd` | Issue | `stage:todo` / `stage:propose` / `stage:apply` / `stage:archive` | `todo` / `propose` / `apply` / `archive` |
| `sdd` | PR | `propose` / `apply` / `archive` | そのまま |
| `label` | Issue | `To Do` / `In Progress` / `Done` | そのまま |
| `label` | PR | （段階ラベルは付かない） | `-` |

段階ラベルが 1 つも無い主体は `-` を出す。段階ラベルが 2 つ以上ある主体は**段階順で最初の 1 つ**を出す。段階が 2 つ以上ある主体は進行中タブに入り得る（`human-turn-classify` の進行中の規則 4 / 5 と規則 2 / 3 は段階ラベルの件数を見ずに `in-progress` を返し、段階が 2 つ以上のときの局面 F の判定はその後ろにある。`stage:propose` + `stage:apply` + `question` の issue がこれに当たる）ので、この場合を決めないと列の値が未定義になる。

列に収まらない語は他の列と同じ規則で表示幅 10 に切り、末尾を `…` にする（`label` 方式の `In Progress` がこれに当たる）。

段階順は `todo` → `propose` → `apply` → `archive`（`label` 方式は `To Do` → `In Progress` → `Done`）とし、段階を持たない主体をその後に置く。この順は Requirement「Model は Card をタブ別に並べ、選択行を 1 つ持つ」の進行中タブの第 2 キーでもある。

他の 3 タブの種別の列は変えない。

- **THEN** その行の種別の列は `-` である

### Requirement: 進行中タブの段階ラベル名に色を付ける
進行中タブの種別の列に出す段階ラベル名には、Requirement「ラベル名は GitHub のラベル色を背景に、輝度で選んだ黒か白を文字にして描く」（`s33-colorful-labels` が定める）の規則で MUST 色を付ける。色はその行の主体のリポジトリのラベル色の表（Requirement「Model はリポジトリごとのラベル色を持つ」）から、**接頭辞を落とす前の段階ラベル名**（`sdd` 方式の issue なら `stage:archive`）で引く。この change は色の規則を定義し直さない。

色を付けるのは列に出した語の文字の範囲だけで、その前後の空白（列の余白）には色を付けない。段階ラベルが無い `-` と、列幅で切られたときの `…` には色を付けない規則を持たず、`…` は背景色の範囲に入ってよい（切り詰めが末尾の記号をスタイル適用中の位置に書くため）。色が引けないとき（`ListLabels` が失敗したリポジトリ、表に無いラベル名、値が空、16 進 6 桁として読めない）は色を付けずに語を描く。

この Requirement は、`s33-colorful-labels` が「ラベル名は GitHub のラベル色を背景に…」で定めた「行全体に色を付ける描画（キューの表の種別の色）の中には色を置かない」という除外に当たらない。進行中の行は行全体の色を持たないので、外側のスタイルが無く、内側のリセットで背景が落ちる問題が起きないためである。同 change が「キューの表にラベル列は無い」と書いた前提は、この change が段階の列を足すことで進行中タブについて成り立たなくなる。他の 3 タブの表にラベルを出さない点は変わらない。

### Requirement: 進行中タブの表はリポジトリごとに見出し行で区切る
進行中タブの表は、リポジトリの区切りに見出し行を 1 行 MUST 挟む。見出し行はそのリポジトリの最初の行の直前に置き、次の形とする。

```
── <owner/name> ── <n> 件 ────…
```

`<n>` はそのリポジトリのそのタブの Card の枚数（タイトルの折り返しで増えた行数ではない）。`── <owner/name> ── <n> 件 ` の後を、行の表示幅が端末の幅に達するまで `─` で埋める。`── <owner/name> ── <n> 件 ` が端末の幅に収まらないときは表示幅で切り、`…` を付けない（切った跡が線の一部に見えるようにする）。端末の幅が 0 以下なら空文字列の 1 行にする。見出し行に色を付けない。

行があるリポジトリが 1 つだけのときも見出し行を MUST 出す。「2 つ以上のときだけ出す」とデータで分岐させると、自動更新で 2 つ目のリポジトリの行が増減するたびに見出しが出入りし、表の全行が 1 行ずれる。選択行の添字は変わらないので、利用者が何もしていないのに選択行が画面上を動くことになる。単一リポジトリの利用者が表の高さを 1 行失うより、表示が揺れないことを採る。

見出し行は選択できない。選択行の添字は Card の並びの添字であり、見出し行は描画のときに挟むだけで、`j` / `k` の移動・プレビューの対象・`a` / `t` / `m` / `c` / `o` / `u` の対象を変えない。見出し行は表の高さを消費するので、見出しのぶん表に出るカードが減る（表はスクロールを持たない）。

他の 3 タブの表に見出し行を出さない。取得成功で `Cards` が 0 件のときのヒント（Requirement「取得が成功して Card が 0 件のときは表の領域にヒントを出す」）も変えない。

#### Scenario: 2 つのリポジトリは見出し行で区切られる
