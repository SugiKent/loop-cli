## Purpose

`L` で対象リポジトリのラベル一覧を画面に出し、印を切り替えて選んだ変更を 1 回の書き込みでまとめて反映する経路を定める。対象は issue でも PR でもよく、`t`（`stage:todo` 専用）では触れないラベルをここから付け外しする。

## ADDED Requirements

### Requirement: L は画面の対象のラベル一覧画面を開く

`Model` は画面の状態として、s22 までの 7 つ（キュー / カード詳細 / PR 詳細 / 回答の確認 / merge の確認 / ヘルプ / URL 一覧）に加えて **ラベル一覧** を MUST 持つ。`Update` は `L`（`Shift` + `l` の大文字。小文字の `l` はカンバンの列移動として s17 に予約されたままで、この change では何もしない）を画面の状態ごとに MUST 次のとおり扱う。対象は `a`（s10 `answer-question`）と同じ規則で決まる。

- キュー画面: 選択行の主体（s08 `Subject`）。選択行が無ければ何もしない
- カード詳細画面: 詳細の対象の `Card.Issue`
- PR 詳細画面: 詳細の対象の選択中の PR
- 回答の確認画面 / merge の確認画面 / ヘルプ画面 / URL 一覧画面: 何もしない（それぞれの画面の分岐が先に処理する）

書き込み中（s11 `todo-toggle`「書き込み中は t と a を受け付けない」の状態）なら何もしない。

対象が決まったら、その `Repo` / `Number` / issue か PR かの区別を **`L` を押した時点で写し取り**、一覧を出している間に取得完了（s08）で `Cards` が入れ替わっても、送信のときはこの写しを使う（s14 `merge-pr` が確認画面の対象を押した時点で固定するのと同じ。自動更新は画面の状態を見ないので、一覧を出している間にも走る）。戻り先（`L` を押した画面）も同時に保持する。

続けてラベルの一覧を用意する。`Model` はリポジトリ名をキーにしたラベルの表を持ち、経路は 2 つに分かれる。

- **表にある**: コマンドを返さず、その場でラベル一覧画面に移り、選択位置を先頭にする。書き込み中フラグは立てない
- **表に無い**: `GHClient.ListLabels` を呼ぶコマンドを返し、書き込み中フラグを立て、フッタの右側のステータスに `<Repo> のラベル一覧を取得中` を出す

取得の結果を受け取ったら書き込み中フラグを下ろし、MUST 次のとおり扱う。

- 失敗: 画面を変えず、フッタに `<Repo> のラベル一覧を取得できません: <エラー文字列>` を赤で出す。表には何も入れない
- 0 件: 表に空の並びを入れ、画面を変えず、フッタに `ラベルがありません` を通常の色で出す（s22 の `URL がありません` と同型）
- 1 件以上で、**画面が `L` を押した時点と同じ**: 表に入れ、ラベル一覧画面に移り、選択位置を先頭にする
- 1 件以上で、**画面が変わっている**: 表には入れるが画面は変えず、フッタに `<Repo> のラベル一覧の表示を中止しました（画面が変わりました）` を通常の色で出す（`openspec/specs/merge-pr/spec.md` の「取り直しの間に画面が変わったら確認画面に移らない」と同じ理由。取得中も `o` / `?` / `u` / `Esc` は動くので、開いたヘルプ画面や URL 一覧をあとから届いた一覧が踏み潰さないようにする）

表は `R`（s12 `manual-refresh`）でも自動更新（s13）でも捨てない。プロセスが終わるまで保持する。したがって、他の経路でラベルを新しく作っても、loop-cli を起動し直すまで一覧には出ない。`ListLabels` は 100 件で切れるが、切れていることは画面に出さない。

#### Scenario: カード詳細の L は Issue を対象にする

- **THEN** 画面はキューのままで、フッタに `org/app のラベル一覧を取得できません:` と `HTTP 403` が含まれる

- **THEN** 画面はヘルプのままで、フッタに `org/app のラベル一覧の表示を中止しました（画面が変わりました）` が含まれる

#### Scenario: 0 行のタブと確認画面とヘルプ画面と URL 一覧で L は何もしない

- **WHEN** `example` の `Result` を渡して異常タブ（0 行）に切り替えた `Model` に `L` を与え、別に s10 の手順で blocked-by の確認画面に移った `Model` に `L` を与え、別に `?` でヘルプ画面を開いた `Model` に `L` を与え、別に `u` で URL 一覧を開いた `Model` に `L` を与える
- **THEN** どれもコマンドは返らず、画面は変わらず、`Fake.Calls` は空である

#### Scenario: 小文字の l は何もしない

- **WHEN** `example` の `Result` を渡した `Model`（キュー画面）に `l` を与え、別にカード詳細を開いた `Model` に `l` を与える
- **THEN** どちらもコマンドは返らず、画面は変わらない（`l` は s17 のカンバンの列移動の予約のままである）

### Requirement: 一覧画面は Space で印を切り替え Enter で送信し Esc で捨てる

ラベル一覧画面は、対象について「送信後にこうなっていてほしいラベル名の集合」を MUST 持つ。初期値は、`L` を押した時点の画面の Card が持つラベル（`Issue.Labels` / `PR.Labels`。最後の取得の時点の値）である。

`Model` の `Update` は、画面の状態がラベル一覧のとき、キー入力を MUST 次のとおり扱う。

- `j` / `↓`: 選択を 1 つ下へ。末尾では動かない（循環しない）
- `k` / `↑`: 選択を 1 つ上へ。先頭では動かない
- `Space`: 選択中の行のラベル名を集合に足す（無ければ）か、集合から外す（あれば）。`gh` は呼ばず、コマンドも返さない
- `Enter`: 送信する（Requirement「送信は読み直して差分を作り 1 回で書き込む」）
- `Esc`: 集合を捨てて戻り先の画面に戻る。戻り先の状態（タブ・選択行・詳細の対象・選択中の PR・展開状態・スクロール位置）は開く前のまま。戻り先がカード詳細 / PR 詳細なら本文領域の内容と寸法を作り直す（s12 `help-screen` / s22 `url-picker` と同じ理由）
- `q` / `Ctrl+C`: 終了コマンドを返す
- 他のキー（`L` / `l` / `a` / `t` / `m` / `o` / `?` / `u` / `R` / `x` / `g` / `1`〜`4` / `Tab` を含む）: 何もしない。`L` も含めるので、一覧を出したまま `L` を押しても戻り先は上書きされない

`Update` はラベル一覧画面の振り分けを `a` / `t` / `m` / `o` / `?` の判定より前（URL 一覧画面の振り分けの直後）に置き、`L` のハンドラをその後ろに置く（後ろに置くと、一覧の裏にある対象に対して回答・ラベル書き込み・ブラウザ起動が起きる）。一覧を出している間に取得完了（s08）・投稿結果（s10）・切り替え結果（s11）・ブラウザで開く結果（s12）・merge の結果（s14）のメッセージが届いたら、各 change の規則どおりに処理し、画面はラベル一覧のままにする。端末サイズの変更も受け取り、一覧の幅と高さに反映する。

#### Scenario: j と k で選択が動く

- **WHEN** ラベルが 3 件ある fixture でラベル一覧を開いた `Model` に、`j` を 3 回、`k` を 1 回与える
- **THEN** 選択位置は順に 1、2、2、1 になる

#### Scenario: Space は印を切り替えるだけで gh を呼ばない

- **WHEN** ラベル一覧を開いた `Model` に `Space` を 1 回与える
- **THEN** コマンドは返らず、`Fake.Calls` に `ListLabels` 以外は無く、画面はラベル一覧のままである

#### Scenario: Space を 2 回押すと元に戻る

- **WHEN** 対象に `wip` が付いている状態でラベル一覧を開き、`wip` の行で `Space` を 2 回与えてから `Enter` を与える
- **THEN** 送信のコマンドは返るが、実行して得たメッセージの後の `Fake.Calls` に `EditIssueLabels` / `EditPRLabels` は無い（変更が 0 件のため）

#### Scenario: Esc は変更予定を捨てる

- **WHEN** ラベル一覧を開いて `Space` を 1 回与えた `Model` に `Esc` を与え、もう一度 `L` を与えて一覧を開き直す
- **THEN** `Esc` の後の画面は戻り先で、`Fake.Calls` に `EditIssueLabels` / `EditPRLabels` は無く、開き直した一覧の印は Card のラベルどおりに戻っている

#### Scenario: 一覧画面で他のキーは何もしない

- **WHEN** ラベル一覧を開いた `Model` に `L`、`l`、`a`、`t`、`m`、`o`、`?`、`u`、`R`、`x`、`g`、`2` を 1 つずつ与える
- **THEN** どのキーでもコマンドは返らず、画面はラベル一覧のまま、選択位置と戻り先と変更予定は変わらず、`Fake.Calls` に `ListLabels` 以外は無く、スタブ `Editor` は呼ばれない

#### Scenario: 一覧画面でも q で終了する

- **WHEN** ラベル一覧を開いた `Model` に `q` を与える
- **THEN** 終了コマンドが返る

### Requirement: 一覧画面は見出しとラベルの行とフッタを出す

画面の状態がラベル一覧のとき、`View` は端末の幅と高さの全体を使い、上から MUST 次の順で描く。

1. 見出し `ラベルを付け外し（変更 <n> 件）`。`<n>` は今の集合と Card のラベルの差分の件数
2. 空行
3. ラベルの行。1 行は `<選択の印><状態の印> <名前>  <説明>` で、選択の印は選択中の行が `▶ `、他の行が空白 2 列。名前と説明の間は空白 2 列で、説明が空のときは名前で終わる。状態の印は次の 4 つ

| 印 | 意味 |
| --- | --- |
| `[x]` | 今付いていて、送信しても変わらない |
| `[ ]` | 今付いておらず、送信しても変わらない |
| `[+]` | 今付いておらず、送信すると付く |
| `[-]` | 今付いていて、送信すると外れる |

4. 残りの高さは空行
5. 最終行はフッタ。左は `j/k 選択  Space 切替  Enter 送信  Esc 戻る  q 終了`、右は s08 と同じステータス（スピナー / エラー / 書き込みステータス）

各行は端末の幅で切り詰める。ラベルの件数が表示できる行数（端末の高さ − 見出し 1 行 − 空行 1 行 − フッタ 1 行）を超えるときは、選択中の行が必ず見えるように表示の開始位置をずらす（s22 `url-picker` の一覧と同じ規則）。一覧はスクロール位置を独立に持たず、選択位置だけを持つ。ラベルの色（`gh label list` の `color`）は使わない。

#### Scenario: 一覧の行と見出しとフッタ

- **WHEN** 対象に `wip` が付いていて、リポジトリのラベルが `docs`（説明あり）と `wip`（説明あり）の 2 件の状態でラベル一覧を開いた `Model`（幅 80・高さ 24）の `View` から ANSI エスケープを除いて読む
- **THEN** 1 行目は `ラベルを付け外し（変更 0 件）` で、`▶ [ ] docs` を含む行と `[x] wip` を含み `▶` を含まない行がこの順で含まれ、最終行に `j/k 選択`、`Space 切替`、`Enter 送信`、`Esc 戻る`、`q 終了` が含まれる

#### Scenario: 印は Space で変わり見出しの件数も動く

- **WHEN** 上の `Model` に `Space` を与えて `View` を読み、続けて `j` と `Space` を与えて `View` を読む
- **THEN** 1 回目は 1 行目が `ラベルを付け外し（変更 1 件）` で `[+] docs` を含む。2 回目は 1 行目が `ラベルを付け外し（変更 2 件）` で `[+] docs` と `[-] wip` の両方を含む

#### Scenario: 件数が高さを超えると選択に追従して表示がずれる

- **WHEN** ラベルを 30 件（`label-00` から `label-29`）持つ fixture でラベル一覧を開いた `Model`（幅 80・高さ 10。表示できる行数は 7）で、`View` を読んでから `j` を 10 回与えて `View` を読む
- **THEN** 1 回目は `label-00` を含み `label-07` を含まない。2 回目は `label-10` を `▶` の行として含み、`label-00` を含まない

### Requirement: 送信は読み直して差分を作り 1 回で書き込む

`Enter` を受けたら `Model` は `internal/action` の関数を呼ぶコマンドを MUST 返し、書き込み中フラグを立て、フッタの右側に `<Repo> #<Number> のラベルを更新中` を出す。関数は写し取った対象（`action.Target`）と、画面が持つ「送信後にこうなっていてほしいラベル名の集合」を受け取り、MUST 次の順で処理する。`ctx` は 30 秒のタイムアウト付き（s10 / s11 / s12 / s14 と同じ値）。

1. `Target.IsPR` が true なら `ViewPR`、false なら `ViewIssue` で対象の現在のラベルを読み直す（画面の Card のラベルは最後の取得の時点のもので、その後に他の経路で変わっていると差分がずれるため。s11 の `ToggleTodo` が読み直すのと同じ理由）
2. 「集合にあって現在に無い」を付ける名前の並び、「現在にあって集合に無い」を外す名前の並びにする。どちらも名前の昇順に並べる（`gh` に渡す引数を決定的にするため）
3. どちらも空なら `gh` を呼ばずに戻る
4. `Target.IsPR` が true なら `EditPRLabels`、false なら `EditIssueLabels` を **ちょうど 1 回** 呼ぶ

読み直しの失敗と書き込みの失敗は、そのままエラーとして返す。ラベル名による拒否（`stage:*` を書かせないなどの判定）は行わない。人が一覧から明示的に選んだラベルはそのまま書く。

この経路は s11 の `ToggleTodo` を呼ばず、`ToggleTodo` もこの経路を使わない。`t` は `stage:todo` 固有の拒否（`ErrOtherStage` / `ErrMultipleStages` / `ErrBlocked`）と 1 ラベルずつの書き込みを保ったままにする。

#### Scenario: 付けると外すが 1 回の呼び出しにまとまる

- **WHEN** 対象が `wip` の付いた issue で、`docs` を `[+]`、`wip` を `[-]` にしてから `Enter` を与え、返ったコマンドを実行する
- **THEN** `Fake.Calls` は `ListLabels` の後に `ViewIssue` と `EditIssueLabels` が 1 件ずつで、`EditIssueLabels` の `AddLabels` は `["docs"]`、`RemoveLabels` は `["wip"]` である

#### Scenario: 対象が PR なら EditPRLabels を呼ぶ

- **WHEN** PR 詳細でラベル一覧を開き、`docs` を `[+]` にして `Enter` を与え、返ったコマンドを実行する
- **THEN** `Fake.Calls` に `EditPRLabels` が 1 件あり、`Number` は選択中の PR の番号、`AddLabels` は `["docs"]` で、`EditIssueLabels` は無い

#### Scenario: 読み直した結果と一致していれば書き込まない

- **WHEN** 対象の fixture に既に `docs` が付いている状態で、画面の Card のラベルには `docs` が無いために `docs` を `[+]` にして `Enter` を与え、返ったコマンドを実行する
- **THEN** `Fake.Calls` に `ViewIssue` はあるが `EditIssueLabels` は無い

#### Scenario: 変更が 0 件なら読み直しもしない

- **WHEN** 印を 1 つも切り替えずに `Enter` を与え、返ったコマンドを実行する
- **THEN** `Fake.Calls` に `ViewIssue` と `EditIssueLabels` と `EditPRLabels` は無い

#### Scenario: 段階ラベルも拒否されない

- **WHEN** `stage:propose` の付いた issue 108 でラベル一覧を開き、`stage:apply` を `[+]` にして `Enter` を与え、返ったコマンドを実行する
- **THEN** `Fake.Calls` に `EditIssueLabels` が 1 件あり、`AddLabels` は `["stage:apply"]` である

#### Scenario: 更新中の表示

- **WHEN** `docs` を `[+]` にして `Enter` を与えた直後（返ったコマンドを実行する前）に `View` から ANSI エスケープを除いて読む
- **THEN** フッタに `org/app #140 のラベルを更新中` が含まれる

### Requirement: 送信の結果をステータスに出し、元の画面に戻る

送信のコマンドは、付けた名前の並び・外した名前の並び・エラーを運ぶ `internal/ui` 内のメッセージを返す。`Model` はそのメッセージを受け取ったら書き込み中フラグを下ろし、**画面をラベル一覧から戻り先の画面に戻し**、フッタの右側（s10 / s11 / s12 / s14 と同じ 1 つのステータス）に MUST 次を出す。

- 書き込んだ（エラー nil、どちらかの並びが空でない）: `<Repo> #<Number> のラベルを更新しました（<変更>）`。`<変更>` は付けた名前を `+<名前>`、外した名前を `-<名前>` として、付ける分・外す分の順に空白区切りで並べる（例 `+docs -wip`）
- 変更が無かった（エラー nil、どちらの並びも空）: `<Repo> #<Number> のラベルに変更はありません`
- エラー（読み直しの失敗、書き込みの失敗のいずれも）: `<Repo> #<Number> のラベルを更新できません: <エラー文字列>` を赤で出す

戻り先がカード詳細 / PR 詳細なら、戻るときに本文領域の内容と寸法を作り直す。成否にかかわらず `Cards` と最終更新時刻と詳細の対象を変えず、Card の `Labels` も書き換えず、取得のコマンドを返さない（反映は s12 の `R` か s13 の自動更新による。s11 `todo-toggle` と同じ扱い）。このステータスは次の取得が始まったとき、または次に `a` / `t` を押したときに消える。

#### Scenario: 更新の結果がフッタに出て元の画面に戻る

- **WHEN** Requirement「送信は読み直して差分を作り 1 回で書き込む」の 1 つ目の Scenario の手順を行い、返ったメッセージを `Update` に渡して `View` から ANSI エスケープを除いて読む
- **THEN** 画面は `L` を押した画面に戻っており、フッタに `のラベルを更新しました（+docs -wip）` が含まれ、その行の Card の `Labels` は変わっていない

#### Scenario: 変更が無かったときの表示

- **WHEN** 印を 1 つも切り替えずに `Enter` を与え、返ったメッセージを `Update` に渡して `View` を読む
- **THEN** 画面は戻り先で、フッタに `のラベルに変更はありません` が含まれる

#### Scenario: 書き込みの失敗は赤で出る

- **WHEN** `*gh.Fake` を埋め込んで `EditIssueLabels` だけがエラー `gh issue edit 140 -R org/app --add-label docs: exit 1: HTTP 403` を返す型を `client` にして、`docs` を `[+]` にしてから `Enter` を与え、返ったコマンドを実行して得たメッセージを `Update` に渡し、`View` から ANSI エスケープを除いて読む
- **THEN** 画面は戻り先で、フッタに `のラベルを更新できません:` と `HTTP 403` が含まれ、`Cards` は変わらない

#### Scenario: 送信のあと L を押すと印は Card のラベルのまま

- **WHEN** 1 つ目の Scenario の手順の後に、同じ行で `L` を与えて一覧を開き直す
- **THEN** `docs` の印は `[ ]`、`wip` の印は `[x]` である（`Cards` を書き換えないため、印は最後の取得の時点のままである）
