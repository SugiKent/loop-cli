## MODIFIED Requirements

### Requirement: ヘルプ画面は実装済みのキーだけを一覧する
ヘルプ画面の `View` は、端末の幅と高さの全体を使い、上から MUST 次の順で描く。
1. 見出し `キーバインド`
2. 空行
3. キーの行。各行は、キーの表記を表示幅 16 に空白で埋めた列に続けて動作の説明を置く（`<キー（16 列）><説明>`）。行の順序と内容は次のとおりで、この change の時点で実装済みのキーだけを出す。前半は mvp.md キーバインド表の順、後半は表に無いキー（s09 / s08 の design.md 未決事項で決めたもの）である

```
j / k / ↑ / ↓   行移動（キュー）/ スクロール（詳細）
1–4 / Tab       タブ切替（今やる / バックログ / 進行中 / 異常）
Enter           詳細を開く / PR を開く（カード詳細）
a               回答・コメント（$EDITOR を開く）
t               stage:todo / To Do を付ける / 外す
L               ラベルを一覧から付け外し
m               PR を merge する（確認あり）
c               issue / PR を close する（確認あり）
n               選択中の repo に issue を作る（確認あり）
o               ブラウザで開く
u               URL 一覧を開く（セッション URL を含む）
g               PR ↔ issue を相互ジャンプ（詳細）
R               全件再取得（キュー）/ セッション取得（詳細）
?               ヘルプを開く / 閉じる
q               終了
Esc             1 つ前の画面に戻る（詳細 / ヘルプ）
Tab             PR 選択（カード詳細）
x               routine コメントの展開 / 折りたたみ（詳細）
PgUp / PgDn     ページ単位のスクロール（詳細）
G               本文の末尾へ飛ぶ（詳細）
```

`t` の行が 2 つのラベル名を並べるのは、付けるラベルがリポジトリの方式で決まるからである（`sdd` は `stage:todo`、`label` は `To Do`）。ヘルプは画面ごとの一覧であり、選択中のカードの方式では出し分けない。
`L` の行は `t` の次に置く。どちらもラベルを触るキーで、`t` が `stage:todo` / `To Do` 専用なのに対し `L` は任意のラベルを扱う（s28 `label-picker`）。小文字の `l` は s17 のカンバンの列移動の予約のままなので出さない。
`G` の行は `PgUp / PgDn` の次（キーの行の末尾）に置く。どちらも本文領域を送るキーで、mvp.md キーバインド表に無い後半のまとまりに属する（`card-detail`「詳細の本文領域はスクロールし、ヘッダ領域は固定する」）。
`R` の行と `u` の行は s31 `session-pane` で書き換えた。`R` は詳細画面で Claude Code セッションの取得を始めるようになり、キュー画面の全件再取得と振る舞いが分かれた（`manual-refresh`「R はキュー画面で全件を再取得し、取得中は無視する」の MODIFIED）。`u` の一覧には右ペインのセッション URL が `session` の出典で入る（`url-picker` の MODIFIED）。どちらも行は増やさず、この時点でキーの行は 19 行である。セッション URL を開く専用のキーは足さない（s31 design.md）。
4. 残りの高さは空行
5. 最終行はフッタ。左は `? / Esc 閉じる  q 終了`、右は s08 と同じステータス（スピナー / エラー / 書き込みステータス）

mvp.md キーバインド表にあって未実装のキー（`v` / `h` / `l` / `←` / `→` / `A` / `s` / `/`）は出さない（`l` はカンバンの列移動であり、`L` とは別のキーである）。`m` は s14 が実装したので mvp.md キーバインド表の順（`t` の次）に足し、`c` は s26 `close-issue-pr` が同じ順（`m` の次。そちらが mvp.md キーバインド表に足す位置）に、`n` は s15 が実装したので同じ順（`c` の次）に足した。`p` は s21 でキュー画面の 2 ペインが常設になり切替の意味を失ったので出さない。後続 change は自分のキーを実装したときに、この Requirement を MODIFIED で写して行を足す（`s`、s16 `A`、s17 `v` / `h` / `l` / `←` / `→`、s19 `/`）。見出しと空行とキーの行が端末の高さ − 1（フッタ）に収まらないときは末尾から切り、スクロールは持たない（design.md 未決事項の既定値。行数は 22 で、`Model` の既定の高さ 24 に収まる）。各行は端末の幅で切り詰める。

#### Scenario: 実装済みのキーの行が順に出る
- **WHEN** `example` の `Result` を渡してヘルプ画面を開いた `Model`（幅 80・高さ 24）の `View` から ANSI エスケープを除いて読む
- **THEN** 1 行目は `キーバインド` で、`j / k / ↑ / ↓` と `行移動（キュー）/ スクロール（詳細）` を含む行、`t` で始まり `stage:todo / To Do を付ける / 外す` を含む行、`L` で始まり `ラベルを一覧から付け外し` を含む行、`m` で始まり `PR を merge する（確認あり）` を含む行、`c` で始まり `issue / PR を close する（確認あり）` を含む行、`n` で始まり `選択中の repo に issue を作る（確認あり）` を含む行、`o` で始まり `ブラウザで開く` を含む行、`u` で始まり `URL 一覧を開く（セッション URL を含む）` を含む行、`R` で始まり `全件再取得（キュー）/ セッション取得（詳細）` を含む行、`?` で始まり `ヘルプを開く / 閉じる` を含む行、`PgUp / PgDn` で始まり `ページ単位のスクロール（詳細）` を含む行、`G` で始まり `本文の末尾へ飛ぶ（詳細）` を含む行がこの順で含まれ、キーの行は 20 行である

#### Scenario: 切替を失った p の行は出ない
- **WHEN** 同じ `View` を読む
- **THEN** `表とプレビューの切替` を含む行は無い

#### Scenario: 未実装のキーは出ない
- **WHEN** 同じ `View` を読む
- **THEN** `即着手`、`カンバン`、`絞り込み`、`review thread` は含まれない

#### Scenario: ヘルプ画面のフッタ
- **WHEN** 同じ `View` を読む
- **THEN** 最終行に `? / Esc 閉じる` と `q 終了` が含まれ、`Enter 開く` と `1-4/Tab タブ` は含まれない

#### Scenario: 低い端末では末尾の行を切る
- **WHEN** ヘルプ画面を開いた `Model` に幅 80・高さ 10 のサイズメッセージを与え、`View` から ANSI エスケープを除いて読む
- **THEN** 行数は 10 で、1 行目は `キーバインド`、最終行はフッタ（`? / Esc 閉じる` を含む）であり、`PgUp / PgDn` で始まる行は含まれない

#### Scenario: ヘルプ画面でも取得中のスピナーが出る
- **WHEN** `New` 直後（初回取得中）の `Model` に `?` を与え、`View` から ANSI エスケープを除いて読む
- **THEN** 1 行目は `キーバインド` で、最終行に `取得中` が含まれる
