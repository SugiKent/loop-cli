## MODIFIED Requirements

### Requirement: 一覧画面は見出しとラベルの行とフッタを出す

画面の状態がラベル一覧のとき、`View` は端末の幅と高さの全体を使い、上から MUST 次の順で描く。

1. 見出し `ラベルを付け外し（変更 <n> 件）`。`<n>` は今の集合と**元の集合**の差分の件数
2. 空行
3. ラベルの行。1 行は `<選択の印><状態の印> <名前>  <説明>` で、選択の印は選択中の行が `▶ `、他の行が空白 2 列。名前と説明の間は空白 2 列で、説明が空のときは名前で終わる。状態の印は元の集合と今の集合の組み合わせで決まる次の 4 つ

| 印 | 元の集合 | 今の集合 | 意味 |
| --- | --- | --- | --- |
| `[x]` | あり | あり | 今付いていて、送信しても変わらない |
| `[ ]` | なし | なし | 今付いておらず、送信しても変わらない |
| `[+]` | なし | あり | 送信すると付く |
| `[-]` | あり | なし | 送信すると外れる |

4. 残りの高さは空行
5. 最終行はフッタ。左は `j/k 選択  Space 切替  Enter 送信  Esc 戻る  q 終了`、右は s08 と同じステータス（スピナー / エラー / 書き込みステータス）

各行は端末の幅で切り詰める。ラベルの件数が表示できる行数（端末の高さ − 見出し 1 行 − 空行 1 行 − フッタ 1 行）を超えるときは、選択中の行が必ず見えるように表示の開始位置をずらす（s22 `url-picker` の一覧と同じ規則）。一覧はスクロール位置を独立に持たず、選択位置だけを持つ。

各行の `<名前>` には、`queue-screen`「ラベル名は GitHub のラベル色を背景に、輝度で選んだ黒か白を文字にして描く」のとおり色を付ける。背景色に使うのは、この画面が `L` で取ったラベル一覧（`gh label list` の応答）が持つそのラベルの `color` であり、`internal/ui` の `Model` が持つリポジトリごとのラベル色の表は引かない（この画面は取得したてのラベル定義そのものを並べているので、同じ画面に新旧 2 つの色が混ざらないようにする）。選択の印・状態の印・説明・行の余白には色を付けず、名前の文字の範囲だけを塗る。色が空、または 16 進 6 桁として読めないラベルは色を付けずに描く。

#### Scenario: 一覧の行と見出しとフッタ

- **WHEN** `Labels` が `wip` の issue を持つ手書きの Card と、ラベルが `docs`（説明あり）と `wip`（説明あり）の 2 件の `labels.json` を持つ fixture ディレクトリでラベル一覧を開いた `Model`（幅 80・高さ 24）の `View` から ANSI エスケープを除いて読む
- **THEN** 1 行目は `ラベルを付け外し（変更 0 件）` で、`▶ [ ] docs` を含む行と `[x] wip` を含み `▶` を含まない行がこの順で含まれ、最終行に `j/k 選択`、`Space 切替`、`Enter 送信`、`Esc 戻る`、`q 終了` が含まれる

#### Scenario: 印は Space で変わり見出しの件数も動く

- **WHEN** 上の `Model` に `Space` を与えて `View` を読み、続けて `j` と `Space` を与えて `View` を読む
- **THEN** 1 回目は 1 行目が `ラベルを付け外し（変更 1 件）` で `[+] docs` を含む。2 回目は 1 行目が `ラベルを付け外し（変更 2 件）` で `[+] docs` と `[-] wip` の両方を含む

#### Scenario: 同じ行で Space を 2 回押すと印も件数も戻る

- **WHEN** 上の `Model` に `Space` を 2 回与えて `View` を読む
- **THEN** 1 行目は `ラベルを付け外し（変更 0 件）` で、`[ ] docs` を含み `[+] docs` を含まない

#### Scenario: 件数が高さを超えると選択に追従して表示がずれる

- **WHEN** ラベルを 30 件（`label-00` から `label-29`）持つ `labels.json` の fixture ディレクトリでラベル一覧を開いた `Model`（幅 80・高さ 10。表示できる行数は 7）で、`View` を読んでから `j` を 10 回与えて `View` を読む
- **THEN** 1 回目は `label-00` を含み `label-07` を含まない。2 回目は `label-10` を `▶` の行として含み、`label-00` を含まない

#### Scenario: 一覧の名前にラベル色が付く

- **WHEN** `docs`（色 `0075ca`）と `wip`（色 `fbca04`）の 2 件を持つ `labels.json` の fixture ディレクトリでラベル一覧を開いた `Model` の `View` を読む
- **THEN** `docs` は背景色 `0075ca` と白の文字色、`wip` は背景色 `fbca04` と黒の文字色で描かれ、`[ ]` / `[x]` の印と説明に色は付かず、ANSI エスケープを除いた各行はこの change の前と一致する

#### Scenario: 色を持たないラベルは色を付けずに描く

- **WHEN** `color` が空文字のラベル 1 件だけを持つ `labels.json` の fixture ディレクトリでラベル一覧を開いた `Model` の `View` を読む
- **THEN** その行は色を指定する ANSI エスケープを 1 つも含まない
