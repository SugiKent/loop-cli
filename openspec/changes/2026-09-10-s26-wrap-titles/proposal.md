# 2026-09-10-s26-wrap-titles

Refs #2

## Why

タイトルは PR を識別する主要な情報なのに、PR 詳細画面のヘッダ 1 行目が端末幅で切り詰められて `…` になり、全文が読めない（#2）。
切り詰めは s09 `card-detail` が design.md 未決事項の既定値として決めたもので、mvp.md が定めた製品の姿ではない。
折り返して全文を出せば、PR のタイトルを読むためにブラウザを開く必要がなくなる。

## What Changes

- PR 詳細画面のヘッダ 1 行目 `<Repo> PR#<Number>  <Title>` を端末幅で折り返し、タイトルを全文出す
- 折り返した 2 行目以降は `<Repo> PR#<Number>  ` の表示幅ぶんインデントし、タイトルの開始位置に縦を揃える
- 折り返しの幅計算は `ansi.StringWidth` ベースで行い、全角文字・絵文字でも桁がずれないようにする
- 折り返しでヘッダが端末の高さを超えないよう、詳細画面のヘッダ領域に上限の規則を足す
- タイトル行以外のヘッダ行（`Summary` / `段階` / `depends on` / PR 一覧 / PR 詳細の labels 行）は今までどおり端末幅で切り詰める

キュー画面の表（Q1）とカード詳細ヘッダの Issue タイトル（Q2）を折り返すかは `## 未確定の判断` で人に問い、回答を得てから spec delta と tasks を足す。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `card-detail`: PR 詳細ヘッダ 1 行目を折り返しにし、ヘッダ領域の切り詰め規則からその行を除く。折り返しでヘッダが端末高を超えないよう上限を定める

Q1 の回答が「表を折り返す」または「プレビューにタイトルを出す」なら `queue-screen` が Modified に加わる。Q2 の回答が「Issue タイトルも折り返す」ならカード詳細ヘッダの Requirement も Modified に加わる。

## Impact

- `internal/ui/detail.go`: `prHeaderLines` が 1 行目を複数行にして返す。`detailHeader` はタイトルが何行あるかを受け取り、高さが足りないときにタイトルの末尾行を落とせるようにする
- `internal/ui/detail_test.go`: PR 詳細ヘッダの折り返しと、高さが足りない端末の振る舞いのテスト
- `internal/ui/view.go` は変更しない。`renderDetail` の `ansi.Truncate` は折り返し済みの行に対して何もしない（`ansi` v0.11.8 の `Truncate` は表示幅が上限以下の文字列をそのまま返す）ので、タイトル行以外を切る役目のまま残る
- Q1 / Q2 の回答次第で `internal/ui/view.go` の `tableRow`、`internal/ui/preview.go` の `previewLines`、`internal/ui/detail.go` の `cardHeaderLines`

## 確定した判断

調査で確定したこと。根拠は `origin/main` のファイルと `ansi` v0.11.8 の実装。

1. **タイトルを画面に描いているのは 3 か所だけ**。`internal/ui` の中で `Title` を描くのは次の 3 か所で、ほかは無い。
   - `internal/ui/view.go:195` が表のタイトル列を `pad(r.title, titleW)` で書く
   - `internal/ui/detail.go:157` がカード詳細のヘッダ 1 行目に `Issue.Title` を書く
   - `internal/ui/detail.go:320` が PR 詳細のヘッダ 1 行目に `PR.Title` を書く
2. **#2 が挙げた `answer.go` / `urls.go` にタイトルは出ていない**。`internal/ui/answer.go:74-77` は `<repo> #<n>` / `<repo> PR#<n>` の `label` を作り、`internal/ui/urls.go:79` はリンクテキストと URL を出す。どちらも `Title` を読まない。
3. **`merge.go` はタイトルを保持しているが描いていない**。`internal/ui/merge.go:148` が `msg.detail.Title` を `m.merge.pr` に取り込むのに、`renderMergeConfirm`（`internal/ui/merge.go:208-239`）は `label`（`<repo> PR#<n>`）と `Body` しか描かない。#2 の「`merge.go` の PR タイトルを含む行」に当たる行は存在しない。merge 確認画面にタイトルを出すかは #2 の依頼（切り詰めをやめる）とは別の追加要望なので、この change では出さない。
4. **`rows.go` は描画しない**。`internal/ui/rows.go` は行のデータ（`row.title`）を作るだけで、描画は `view.go` の `tableRow`。#2 の対象箇所の `rows.go` は `view.go` と読み替える。
5. **PR 一覧の行（`prListRow`）にタイトルは無い**。この行が並べるのは段階と PR 番号と状態と未確定件数と labels と checks だけなので、この change は触らない。
6. **PR 詳細ヘッダの切り詰めは製品の決定ではない**。`openspec/specs/card-detail/spec.md:49` が「端末の幅に切り詰めて末尾を `…` にする（design.md 未決事項の既定値）」と明記している。さらに `docs/mvp/mvp.md:85` のカード詳細ヘッダの定義は「リポジトリ、Issue 番号、現在の段階、バッジ、この段階に入ってからの経過時間」で、タイトルを列挙していない。したがってタイトル行の扱いは s09 の design 既定値であり、折り返しへ変えるのに mvp.md の改訂は要らない。
7. **`ansi.Wrap` は日本語でも表示幅どおりに折る**。`ansi` v0.11.8 の `Wrap`（`wrap.go:267-278`）は「必要なら単語境界を割る」と契約しており、実測でも全角 28 字を幅 20 で折ると各行の表示幅が 20 / 20 / 20 / 20 / 4 になる。英語では単語境界を守って 12 / 14 / 15 / 17 になる。`Wordwrap` は長い語を割らないので、全角 84 幅が 1 行のまま返り使えない。
8. **`ansi.Truncate` は幅以下の文字列に `…` を付けない**。`truncate.go:66-69` が `StringWidth(s) <= length` で入力をそのまま返す。折り返し済みの行に `…` を付けるには `ansi.Truncate(l, width-1, "") + "…"` のように明示的に付ける必要がある（実測で確認）。
9. **詳細画面は今も端末高を超えうる**。`PRs` が空でも `prListLines` は 3 行返す（`internal/ui/detail.go:184-199`）ため、幅 120・高さ 5・`Summary` あり・`PRs` 空のカードでは合計 6 行になる。この経路は折り返しの前から存在するので、この change は「折り返しが原因で超えないこと」だけを引き受け、既存の溢れは直さない。

## 未確定の判断

### Q1. キュー画面の表（一覧）のタイトルも折り返すか

**#2 は `internal/ui/rows.go — 一覧の行に出す PR タイトル` を対象箇所に明示的に挙げ、「PR のタイトルを表示するすべての場所で … 折り返し、全文を表示する」と書いている。下の A / C / D はいずれもその文面から外れる。**

そのうえで、表には次の事情がある。表は端末高の約半分で、スクロールを持たない（`internal/ui/view.go:245` の `cut` が溢れた行を捨てる）。タイトル列の幅は端末幅 − 48（`internal/ui/view.go:13-21` の `colFixed`）なので、幅 80 の端末では 32 列（全角 16 文字）しかない。折り返すと 1 枚のカードが複数行を占め、表に出るカードの枚数が減る。
`docs/mvp/mvp.md:51-73` の画面図は表を 1 カード 1 行で描き、タイトルを `…` で切っているが、同 75-79 行の散文はタイトルの切り詰めに触れていない。図を規範と読むなら B / C は mvp.md の改訂が要り、例示と読むなら要らない。この解釈も含めて判断してほしい。

- 選択肢 A（推奨）: 表は 1 カード 1 行のまま切り詰め、下段プレビューの先頭に選択中カードのタイトルを全文（折り返し）で出す。カーソルを合わせたカードのタイトルは全文読め、表に出るカード枚数は減らない。同じタイトルが表とプレビューに二重に出る。プレビューもスクロールを持たないので、本文が 1〜数行短くなる
- 選択肢 B: 表の全行を折り返す（#2 の文面どおり）。幅 80 の端末で全角 30 文字のタイトルなら 1 カードが 2 行になり、表に出るカードが約半分になる。溢れたカードはスクロールが無いので画面から消える
- 選択肢 C: 表の選択行だけ折り返し、非選択行は切り詰めたままにする。選択中のタイトルを表の中で読める。`j` / `k` でカーソルを動かすたびに表の行位置がずれる
- 選択肢 D: 表もプレビューも変えず、折り返しは詳細画面だけにする。一覧で全文を読む手立ては `Enter` で詳細を開くことだけになる
- 依存: なし

### Q2. カード詳細ヘッダの Issue タイトルも折り返すか

**#2 は一貫して「PR のタイトル」を対象にしており、カード詳細ヘッダ（`internal/ui/detail.go:157`）は対象箇所に挙がっていない。この行が出すのは `Issue.Title` だけで、PR のタイトルは 1 文字も含まない。** そのため #2 の文面どおりなら対象外になる。

一方、表のタイトル列には Issue と PR が混在する（`internal/ui/rows.go:45` の `Subject`）ので、Issue のタイトルだけ切り詰まる状態も残る。

- 選択肢 A（推奨）: Issue のタイトルも折り返す。カード詳細と PR 詳細のヘッダ 1 行目が同じ見た目・同じ規則になり、なぜ片方だけ切れるのかを説明せずに済む。#2 の文面より広い範囲を直すことになる
- 選択肢 B: #2 の文面どおり、PR のタイトルだけを折り返しの対象にする。カード詳細ヘッダの Issue タイトルは今までどおり `…` で切れる。同じ位置の同じ形の行で挙動が分かれる
- 依存: なし
