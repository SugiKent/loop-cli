# 2026-09-10-s26-wrap-titles

Refs #2

## Why

タイトルは Issue / PR を識別する主要な情報なのに、詳細画面のヘッダ 1 行目が端末幅で切り詰められて `…` になり、全文が読めない（#2）。
切り詰めは s09 `card-detail` が design.md 未決事項の既定値として決めたもので、mvp.md が定めた製品の姿ではない。
折り返して全文を出せば、詳細画面でタイトルを読むためにブラウザを開く必要がなくなる。

## What Changes

- カード詳細画面のヘッダ 1 行目 `<Repo> #<Number>  <Title>` を端末幅で折り返し、タイトルを全文出す
- PR 詳細画面のヘッダ 1 行目 `<Repo> PR#<Number>  <Title>` も同じく折り返し、タイトルを全文出す
- 折り返した 2 行目以降は `<Repo> #<Number>  ` の表示幅ぶんインデントし、タイトルの開始位置に縦を揃える
- 折り返しの幅計算は `ansi.StringWidth` ベースで行い、全角文字・絵文字でも桁が崩れないようにする
- ヘッダ 1 行目以外のヘッダ行（`Summary` / `段階` / `depends on` / PR 一覧 / PR 詳細 2 行目）は今までどおり端末幅で切り詰める

キュー画面の表（一覧）のタイトルを折り返すかは `## 未確定の判断` の Q1 で、回答を得てから spec delta と tasks を足す。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `card-detail`: ヘッダ領域の切り詰め規則を変え、ヘッダ 1 行目（カード詳細・PR 詳細とも）だけ折り返しにする

Q1 の回答が「表を折り返す」または「プレビューにタイトルを出す」なら `queue-screen` も Modified に加わる。

## Impact

- `internal/ui/detail.go`: `cardHeaderLines` / `prHeaderLines` が 1 行目を複数行にして返す。`detailHeader` の本文領域高の計算はヘッダ行数から引く既存の式のままで、折り返しで増えた行も自然に本文領域から引かれる
- `internal/ui/view.go`: `renderDetail` がヘッダの各行を `ansi.Truncate` する。折り返し済みの 1 行目を再度切らないようにする
- `internal/ui/detail_test.go` / `view_test.go`: 切り詰めを期待している既存テストの更新
- Q1 の回答次第で `internal/ui/view.go` の `tableRow` または `internal/ui/preview.go` の `previewLines`

## 確定した判断

調査で確定したこと。根拠は `origin/main` のファイル。

1. **タイトルを画面に出しているのは 3 か所だけ**。次の 3 か所が `Title` を読む。
   - `internal/ui/view.go:195` が表のタイトル列を `pad(r.title, titleW)` で書く
   - `internal/ui/detail.go:157` がカード詳細のヘッダ 1 行目を書く
   - `internal/ui/detail.go:320` が PR 詳細のヘッダ 1 行目を書く
2. **#2 が挙げた `answer.go` / `merge.go` / `urls.go` にタイトルは出ていない**。3 つとも `label`（`internal/ui/answer.go:74-77` の `<repo> #<n>` / `<repo> PR#<n>`）か URL のリンクテキストを出しており、`Title` を参照していない。よってこの change では触らない。
3. **`rows.go` は描画しない**。`internal/ui/rows.go` は行のデータ（`row.title`）を作るだけで、描画は `view.go` の `tableRow`。#2 の対象箇所の `rows.go` は `view.go` と読み替える。
4. **PR 一覧の行（`prListRow`）にタイトルは無い**。この行が並べるのは段階と PR 番号と状態と未確定件数と labels と checks だけなので、この change は触らない。
5. **詳細ヘッダの切り詰めは製品の決定ではない**。`openspec/specs/card-detail/spec.md:49` が「端末の幅に切り詰めて末尾を `…` にする（design.md 未決事項の既定値）」と明記している。mvp.md の「カード詳細」に切り詰めの指定は無い。したがって折り返しへ変えるのは spec の変更で済み、mvp.md の改訂は要らない。
6. **表の切り詰めは製品の決定である**。`docs/mvp/mvp.md:53-60` の画面構成は表を 1 カード 1 行で描き、タイトルを `…` で切っている。`openspec/config.yaml` の rules は「docs/mvp と docs/domain に無い仕様を発明しない」。表を折り返すと mvp.md の改訂が要るので、Q1 として人に問う。
7. **Issue のタイトルも同じ扱いにする**。表のタイトル列とカード詳細ヘッダ 1 行目に出るのは Issue のタイトルで、#2 は「PR タイトル」と書いているが、表の同じ列に Issue と PR が混在する（`internal/ui/rows.go:45` の `Subject`）。列ごとに挙動を変えると読み手が理由を説明できないので、Issue と PR を区別せず「タイトル」として扱う。
8. **折り返しでヘッダが画面を溢れる経路がある**。`detailHeader`（`internal/ui/detail.go:141-151`）は本文 1 行を確保するために PR 一覧を末尾から落とすが、固定ヘッダ自体が端末高を超える場合は守られていない。折り返しでこの経路が現実的になるので、design.md でヘッダ領域の上限を定める。

## 未確定の判断

### Q1. キュー画面の表（一覧）のタイトルも折り返すか

表は端末高の約半分で、スクロールを持たない（`internal/ui/view.go:245` の `cut` が溢れた行を捨てる）。タイトル列の幅は端末幅 − 48 なので、幅 80 の端末では 32 列（全角 16 文字）しかない。折り返すと 1 枚のカードが複数行を占め、表に出るカードの枚数が減る。

- 選択肢 A（推奨）: 表は 1 カード 1 行のまま切り詰め、下段プレビューの先頭に選択中カードのタイトルを全文（折り返し）で出す。カーソルを合わせたカードのタイトルは常に全文読め、表に出るカード枚数は減らない。プレビューの本文が 1〜数行短くなる。mvp.md は表の記述を変えず、プレビューの記述に 1 行足す
- 選択肢 B: 表の全行を折り返す（#2 の文面どおり）。幅 80 の端末で全角 30 文字のタイトルなら 1 カードが 2 行になり、表に出るカードが約半分になる。溢れたカードはスクロールが無いので画面から消える。mvp.md の画面構成の改訂が要る
- 選択肢 C: 表の選択行だけ折り返し、非選択行は切り詰めたままにする。選択中のタイトルを表の中で読める。`j` / `k` でカーソルを動かすたびに表の行位置がずれる。mvp.md の画面構成の改訂が要る
- 選択肢 D: 表もプレビューも変えず、折り返しは詳細画面だけにする。一覧で全文を読む手立ては `Enter` で詳細を開くことだけになる
- 依存: なし
