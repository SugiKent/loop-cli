# design: 2026-09-10-s27-wrap-titles

Refs #2

## Context

タイトルを描く 3 か所は、どれも「1 行を組み立てて幅で切る」形になっている。

- `internal/ui/view.go` の `tableRow` は固定列を `pad` で連ね、タイトル列も `pad(r.title, titleW)` で切り、最後に `ansi.Truncate(line, m.width, "")` を通して 1 行を返す。`tableLines` がそれを行ごとに集め、`cut(lines, h)` で表の高さに切る
- `internal/ui/detail.go` の `cardHeaderLines` / `prHeaderLines` はヘッダ行を `[]string` で返し、`renderDetail` が各行を `ansi.Truncate(l, m.width, "…")` に通す
- 本文領域の高さは `detailHeader` が `max(m.height-2-len(header), 1)` で決め、1 行を割るときは PR 一覧を末尾から落とす

列幅の定数は `view.go:13-21` にあり、`colFixed` は 2 + 4 + 10 + 20 + 7 + 5 = 48。タイトル列は先頭から 43 列目で始まり、幅は `m.width - 48`、その右に経過の 5 列が続く。

制約は 4 つある。

- 表示幅は `github.com/charmbracelet/x/ansi` の `StringWidth` で測る。既存コードはすべてこれを使っており、`len` や `utf8.RuneCountInString` は使わない
- `detailHeader` は `[]string` を不透明に受け取るので、今のままではどの要素がタイトル行かを区別できない
- 表はスクロールを持たない。折り返しで増えた行はそのぶん表から溢れる
- 折り返しでヘッダが伸びると本文領域が痩せる。`detailHeader` は本文領域の高さをヘッダの行数から引いて出すので、折り返しで増えた行もそのまま引かれる。ただし固定ヘッダ自体が端末高を超える経路が、折り返しによって新たに現実的になる

`card-detail` のヘッダの Requirement は、先行する `s26-issue-label-driven`（issue #5）も MODIFIED している。
この change の delta はその版を土台に組んであり、apply / archive の順序が入れ替わると片方の変更が消える。
詳しくは proposal の「先行 change への依存」を読む。

## Goals / Non-Goals

**Goals:**

- タイトルを出している 3 か所すべてで全文を読めるようにする
- 折り返した行をタイトルの開始位置に縦揃えし、どこからがタイトルの続きかを目で追えるようにする
- 全角文字・絵文字を含むタイトルで桁がずれないようにする
- 折り返しを原因として画面の行数が端末の高さを超えないようにする

**Non-Goals:**

- キュー画面の表にスクロールを入れること（mvp.md にキーが無い）
- 折り返しと無関係に既に存在する高さ超過の経路を直すこと（proposal の「確定した判断」11）
- 本文（Glamour が折り返す）・フッタ・PR 一覧・labels 行の折り返し
- 詳細ヘッダのスクロール（ヘッダ領域は固定のまま）

## Decisions

### D1. 折り返しは `ansi.Wrap` を使う

`ansi` v0.11.8 の `Wrap`（`wrap.go:267-278`）は「必要なら単語境界を割る」と契約している。実測では全角 28 字を幅 20 で折ると各行の表示幅が 20 / 20 / 20 / 20 / 4 になり、英語の文では単語境界を守って 12 / 14 / 15 / 17 になる。日本語タイトルでは幅どおりに折れ、英語混じりのタイトルでは単語が途中で切れない。
幅の計算は `GraphemeWidth`（`width.go:66-68`）で、`StringWidth` と同じ規則なので、Scenario が検証する表示幅と一致する。

実装しながら実測で分かった `ansi.Wrap` の性質が 2 つある。どちらも仕様に取り込む。

- **幅 2 未満では幅を守れない。** 全角 1 文字（幅 2）が入らない幅では折り返しようがなく、幅 1 では先頭に空行を作って以降の各行の表示幅が 2 になる（`wrapToWidth("あああ", 1)` → `["", "あ", "あ", "あ"]`）。`wrapToWidth` は `w < 2` で折らずに 1 行を返し、表は `titleW < 2`（端末幅 49 以下）でタイトルを出さない分岐へ落とす。これを入れないと、幅 49 の端末で `pad` が各断片を `…` 1 文字に切り詰め、Card 1 枚が「文字数 + 1」行を占めて表を埋め尽くす
- **折り返し位置の空白 1 個は消える。** `addNewline`（`wrap.go:331-336`）が改行に置き換えた空白を出力しないので、行を連結しても元の文字列には戻らない。表示は自然なままなので `Wrap` を採る判断は変えないが、Scenario の「連結すると `Title` と一致」は空白を除いて比べる形に直した

- 代替案: `ansi.Hardwrap`。実測で日本語の結果は `Wrap` と同一だが、英語では単語の途中で割る（20 / 20 / 20 / 1）。読みやすさで劣るので採らない
- 代替案: `ansi.Wordwrap`。長い語を割らないので、空白の無い日本語タイトルが 1 行のまま（表示幅 84）返る。幅の保証が崩れるので採らない
- 代替案: `lipgloss` の `Style.Width()`。行数を数える前にレンダリングが要るうえ、Lip Gloss は右側を空白で埋めるので既存の連結と噛み合わない（`emptyHintLines` が同じ理由で Lip Gloss の配置関数を避けている）

### D2. 分割そのものは 1 つの関数にまとめ、体裁は呼ぶ側が付ける

表と詳細では、折り返した後に付ける体裁が違う。表は継続行に 43 列の空白と経過列ぶんの空白を足し、詳細は接頭辞と同じ幅の空白だけを足す。共通なのは「表示幅 w で分割する」ところだけなので、そこだけを関数にする。

```go
// wrapToWidth は s を表示幅 w 以下の行に割る。w が 1 未満なら s の 1 行を返す。
func wrapToWidth(s string, w int) []string
```

詳細側は接頭辞を扱う分だけ薄い関数をもう 1 つ置く。呼ぶ側が `cardHeaderLines` と `prHeaderLines` の 2 か所あるので、重複を避ける意味がある。

```go
// wrapTitle は `<prefix><title>` を幅 width に収めた行に割り、2 行目以降を prefix の表示幅ぶん字下げする。
func wrapTitle(prefix, title string, width int) []string
```

`wrapTitle` は `wrapToWidth(title, width - StringWidth(prefix))` の結果に、1 行目は接頭辞を、2 行目以降は同じ表示幅の空白を前置する。`ansi.Wrap(prefix+title, width, "")` を素直に呼ぶと 2 行目以降が幅いっぱいになり、そこへ字下げを足すと幅を超えるので、この順にする。

境界の扱いを 2 つ決める。

- `width < 1`（初回の `WindowSizeMsg` が届く前の `m.width == 0` を含む）: `prefix + title` の 1 行をそのまま返す。`renderDetail` の `ansi.Truncate` が従来どおり切る
- `width - StringWidth(prefix) < 2`: 全角 1 文字が入らず、`ansi.Wrap` が幅を守れない（D1 の実測）。字下げを諦め、`prefix + title` 全体を幅 `width` で折る。`width < 2` はこの条件に含まれるので、境界は 1 つの式で足りる

### D3. 表は `tableRow` が複数行を返し、経過と `▶` を 1 行目に残す

`tableRow` の戻り値を `[]string` にする。`wrapToWidth(r.title, titleW)` で得た各断片について、

- 1 行目には、今までどおりの固定列（`▶` と優先と種別とリポジトリと番号で 43 列）に `pad(断片, titleW)` を続け、最後に `pad(経過, colElapsed)` を置く
- 継続行には、43 列の空白に `pad(断片, titleW)` を続け、最後に `colElapsed` 列ぶんの空白を置く

どちらも表示幅が `m.width` ちょうどになる。末尾まで空白で埋めるのは、異常（黄の背景）の Card が複数行になったときに背景色が行ごとに途切れないようにするため。1 行目だけが埋まって継続行が短いと、背景の帯が階段状に見える。

`titleW < 2`（端末幅 49 以下）のときはタイトルを出さず、1 行だけを返して端末幅で切る。0 以下ではなく 2 未満なのは、タイトル列に全角 1 文字が入らない幅では折り返しが幅を守れないため（D1 の実測）。

`tableLines` は各 Card の行を平らに並べてから `cut` に渡す。`m.cursor` は今も Card を指しているので、移動のコードはそのままでよい。

### D4. 折り返しは行を組み立てる側で行い、`renderDetail` は変えない

ヘッダの行数は `detailHeader` が本文領域の高さを決めるのに使うので、折り返しは高さ計算より前に済んでいなければならない。
折り返し済みの行はすべて幅以下なので、`renderDetail` の `ansi.Truncate(l, m.width, "…")` はそれらに対して何もしない（`truncate.go:66-69` が `StringWidth(s) <= length` で入力をそのまま返す）。labels 行や PR 一覧の行を切る役目は残るので、`view.go` の `renderDetail` は変更しない。

### D5. ヘッダが端末高を超えるときはタイトルの末尾行から落とす

`detailHeader` は今、PR 一覧を末尾から落として本文 1 行を確保している。PR 一覧を落としても足りないときに、折り返したタイトル行を末尾から落とす。タイトルの 1 行目は必ず残す（残さないとどの Issue / PR を見ているのか分からなくなる）。

これを実装するには `detailHeader` がタイトル行の範囲を知る必要がある。`cardHeaderLines` / `prHeaderLines` が行数を添えて返す形にする。

```go
// cardHeaderLines はカード詳細のヘッダ行と、その先頭何行がタイトル行かを返す。
func (m Model) cardHeaderLines() (lines []string, titleLines int)
```

`detailHeader` は `fixed` の先頭 `titleLines` 行だけを削減の対象にする。

落とした後に残る最後のタイトル行へ `…` を付けるとき、`ansi.Truncate(l, m.width, "…")` は使えない。折り返し済みの行は幅以下なので `Truncate` が何もせず、`…` が付かないためである（実測で確認）。`ansi.Truncate(l, m.width-1, "") + "…"` のように、幅を 1 列空けてから明示的に付ける。

`#2` が直したいのは端末**幅**による切り詰めなので、端末の**高さ**が足りない場合に末尾を諦めることは依頼と衝突しない。高さが足りない端末では、そもそも全文を同時に出す手立てが無い。

- 代替案: ヘッダをスクロールさせる。ヘッダ領域が固定であることは `card-detail` の Requirement で、この change の範囲を超える
- 代替案: `Summary` や `段階` の行を先に落とす。`段階` は `docs/mvp/mvp.md:85` がヘッダの内容として列挙しており、落とすと mvp.md の改訂が要る
- 代替案: 何もしない（行数が端末高を超えるまま）。alt screen（`view.go:41-45`）のフレームが崩れるので採らない

### D6. `docs/mvp/mvp.md` の画面図を描き直す

`docs/mvp/mvp.md:51-73` のキュー画面の図は表を 1 カード 1 行で描き、タイトルを `…` で切っている。折り返しを入れると図と実装がずれるので、図の中の長いタイトルを 2 行に割った形へ描き直す。表の挙動を変える判断は PR #8 で人が下しているので、この change は図をその判断に追随させるだけである。

## Risks / Trade-offs

- **表に出るカードが減る** → 幅 80 の端末で全角 30 文字のタイトルなら 1 枚が 2 行になり、表に出る枚数が約半分になる。スクロールが無いので溢れたカードは見えなくなる。人がこの代償を承知で折り返しを選んでいる（proposal の「確定した判断」7）
- **カーソルが表の外に出る** → 折り返しでカーソルの Card が表の高さより下に来ると、`j` / `k` を押しても選択行が画面に現れないまま移動が進む。既存の「行数が高さを超えると見えなくなる」振る舞いと同じ性質で、折り返しはその頻度を上げる。プレビューは選択中の Card を出し続けるので、何を選んでいるかは下段で分かる
- **既存テストが切り詰めを期待している** → `view_test.go` の `TestLongTitleIsTruncated` 相当と、`detail_test.go` のヘッダのテストを書き換える。spec delta の Scenario がそのまま対応する
- **タイトルが複数行に割れると `strings.Contains(view, title)` で検証できない** → Scenario が定めたとおり、タイトル列（表）またはタイトル行（詳細）を取り出して連結してから `Title` と比較する。画面全体から空白を除いて `Contains` する書き方は、折り返しが壊れていても通ってしまうので使わない
- **本文領域が痩せる** → 長いタイトルの Card では本文が数行減る。本文はスクロールできるので情報は失われない
- **`ansi` の挙動がバージョンで変わる** → `go.mod` の `github.com/charmbracelet/x/ansi` を v0.11.8 に固定したまま使い、Scenario で表示幅を直接検証する

## 未決事項

docs/mvp と docs/domain が沈黙している点。実装者が選ぶ既定値を 1 つずつ示す。

- **折り返しアルゴリズム**: 既定値は `ansi.Wrap`（D1）
- **表の継続行の体裁**: 既定値は 43 列の空白 + タイトルの続き + 経過列ぶんの空白で、行全体を端末幅まで埋める（D3）
- **表の継続行の色と印**: 既定値は 1 行目と同じ色を付け、`▶` と経過は 1 行目にだけ出す（D3）
- **詳細の継続行の字下げ幅**: 既定値は接頭辞 `<Repo> #<Number>  ` の表示幅（#2 が「タイトルの開始位置に合わせてインデントする」と書いている）
- **字下げの余地が無い端末での扱い**: 既定値は字下げを付けず端末幅で折る（D2）
- **全角 1 文字が入らない幅での扱い**: 既定値は折らずに 1 行で返し、表はタイトルを出さない（D1 / D3）
- **折り返し位置の空白の扱い**: 既定値は `ansi.Wrap` のまま 1 個消える。Scenario は空白を除いて連結を比べる（D1）
- **`m.width == 0` の扱い**: 既定値は折り返さず 1 行で返す（D2）
- **高さが足りないときに落とす順**: 既定値は PR 一覧 → タイトルの末尾行（D5）。`Summary` と `段階` は落とさない
- **落としたことの見せ方**: 既定値は残った最後のタイトル行の末尾を `…` にする（D5）
