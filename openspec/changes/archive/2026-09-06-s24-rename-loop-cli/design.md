## 決定

### 開発補助 CLI は `loop-cli-dev`

本体が `loop-cli` になるため `sugi-loop-cli` の受け皿が要る。`loop-cli-dev` は本体名を前置し、開発用であることが名前だけで分かる。利用者の決定。

### 設定・キャッシュのパスも変える。移行処理は書かない

`~/.config/loop-cli/config.yml` / `~/.cache/loop-cli/snapshot.json` にする。利用者の決定。

旧パスを読む・コピーするコードは書かない。設定ファイルが無ければ onboarding のフォームが出る（s08a）ので、利用者は 1 度だけ入れ直せば済む。スナップショットは GitHub から作り直せる派生データで、無ければ起動直後の stale 表示が 1 回抜けるだけである。CLAUDE.md「一度しか使わない処理のために抽象化を増やさない」に従い、一度きりの移行コードを常設しない。

### ヘッダの幅は 1 列縮む。Scenario の幅を実測に合わせる

`sugi-loop`（9 列）→ `loop-cli`（8 列）でヘッダ全体が 1 列縮む。`example` のヘッダは `↻ HH:MM` まで入れて 70 列、`↑ update` も出ているときはちょうど 80 列になる。短縮の規則（`[4]` → `[3]` → `[2]` → `↑ update` → `↻ HH:MM` の順に落とす）は変えず、規則が発火する幅だけがずれる。

実測（`example` の `Result`）:

| 幅 | 印あり | 印なし |
| --- | --- | --- |
| 80 | 短縮なし（ちょうど収まる） | 短縮なし |
| 79 | `[4]` のタブ名が落ちる | 短縮なし |
| 60 | `[2]`〜`[4]` が短縮され印は残る | `[3]` `[4]` が短縮され `[2]` は残る |
| 59 | 印が落ちる | `[2]`〜`[4]` が短縮される |

`queue-screen` の Scenario は、規則の各段（短縮なし / `[4]` だけ落ちる / 右から短縮 / 印を先に落とす）を 1 つずつ踏む幅に付け替える。幅 80 の Scenario は「既定幅で短縮が起きない」ことの検証に変わり、`[4]` が落ちる検証は幅 79 に移す。
