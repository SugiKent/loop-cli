## MODIFIED Requirements

### Requirement: L は画面の対象のラベル一覧画面を開く

`Model` は画面の状態として、s22 までの 7 つ（キュー / カード詳細 / PR 詳細 / 回答の確認 / merge の確認 / ヘルプ / URL 一覧）に加えて **ラベル一覧** を MUST 持つ。`Update` は `L`（`Shift` + `l` の大文字。小文字の `l` はカンバンの列移動として s17 に予約されたままで、この change では何もしない）を画面の状態ごとに MUST 次のとおり扱う。対象は `a`（s10 `answer-question`）と同じ規則で決まる。

- キュー画面: 選択行の主体（s08 `Subject`）。選択行が無ければ何もしない
- カード詳細画面: 詳細の対象の `Card.Issue`
- PR 詳細画面: 詳細の対象の選択中の PR
- 回答の確認画面 / merge の確認画面 / ヘルプ画面 / URL 一覧画面: 何もしない（それぞれの画面の分岐が先に処理する）

書き込み中（s11 `todo-toggle`「書き込み中は t と a を受け付けない」の状態）なら何もしない。

対象が決まったら、`L` を押した時点で MUST 次の 3 つを写し取る。一覧を出している間に取得完了（s08）で `Cards` が入れ替わっても、これらは変えない。

1. 書き先（`Repo` / `Number` / issue か PR かの区別。s14 `merge-pr` が確認画面の対象を押した時点で固定するのと同じ。自動更新は画面の状態を見ないので、一覧を出している間にも走る）
2. **対象に付いているラベル名の集合**（`Card.Issue.Labels` / `PR.Labels`。最後の取得の時点の値）。以降この写しを「元の集合」と呼び、行の印・見出しの変更件数・「変更が無い」の判定はすべてこれを基準にする
3. 戻り先（`L` を押した画面）

続けてラベルの一覧を用意する。`Model` はリポジトリ名をキーにしたラベルの表を持ち、経路は 2 つに分かれる。

- **表にある**: コマンドを返さず、下の「一覧を開く判定」に進む。書き込み中フラグは立てない
- **表に無い**: `GHClient.ListLabels` を呼ぶコマンドを返し、書き込み中フラグを立て、フッタの右側のステータスに `<Repo> のラベル一覧を取得中` を出す。結果を受け取ったら書き込み中フラグを下ろし、失敗なら画面を変えずフッタに `<Repo> のラベル一覧を取得できません: <エラー文字列>` を赤で出す（表には何も入れない）。成功したら表に入れて「一覧を開く判定」に進む

**一覧を開く判定**（2 つの経路が合流する 1 か所。キャッシュの有無で結果が変わってはならない）。

- ラベルが 0 件: 画面を変えず、フッタに `ラベルがありません` を通常の色で出す（s22 の `URL がありません` と同型）
- 1 件以上で、画面が `L` を押した時点と同じ: ラベル一覧画面に移り、選択位置を先頭にする
- 1 件以上で、画面が変わっている: 画面は変えず、フッタに `<Repo> のラベル一覧の表示を中止しました（画面が変わりました）` を通常の色で出す（`openspec/specs/merge-pr/spec.md` の「取り直しの間に画面が変わったら確認画面に移らない」と同じ理由。取得中も `o` / `?` / `u` / `Esc` は動くので、開いたヘルプ画面や URL 一覧をあとから届いた一覧が踏み潰さないようにする）。キャッシュ経路では画面が変わる余地が無いのでこの枝に入らない

表は取得（初回・`R`（s12 `manual-refresh`）・自動更新（s13））が成功するたびに MUST 捨てる。次に `L` を押したときに取り直すので、他の経路でラベルを作っても、次の更新のあとの `L` には出る。s30 で運用方式を毎回の取得で判定し直すようになり、方式は変わるのにこの一覧だけが起動時のまま古く残る状態を作らないための規則である。取得が失敗したときは捨てない（前回の結果を維持する D-002 と同じ扱いで、取り直せない状況で一覧を空にしない）。`ListLabels` は 1000 件で切れるが、切れていることは画面に出さない。

#### Scenario: キュー画面の L はラベルを取りに行く

- **WHEN** `example` の `Result` を渡して今やるタブ（issue 108 + PR 131。主体は PR 131）を選んだ `Model` に `L` を与える
- **THEN** コマンドが返り、画面はキューのままで、`View` のフッタに `org/app のラベル一覧を取得中` が含まれる

#### Scenario: 取得できたら一覧画面に移る

- **WHEN** 上のコマンドを実行して得たメッセージを `Update` に渡す
- **THEN** 画面はラベル一覧で、選択位置は 0、`Fake.Calls` の `ListLabels` は 1 件で `Repo` が `org/app` である

#### Scenario: 2 回目は gh を呼ばない

- **WHEN** 上の手順の後に `Esc` で戻り、もう一度 `L` を与える
- **THEN** コマンドは返らず、画面はすぐラベル一覧になり、`Fake.Calls` の `ListLabels` は 1 件のままである

#### Scenario: PR 詳細の L は選択中の PR を対象にする

- **WHEN** `example` の issue 108 のカード詳細から `Enter` で PR 131 の PR 詳細を開いた `Model` に `L` を与え、返ったコマンドを実行して得たメッセージを `Update` に渡す
- **THEN** 画面はラベル一覧で、書き先は `org/app` の PR 131（PR である）、元の集合は PR 131 の `Labels`（`propose` と `question`）である

#### Scenario: カード詳細の L は Issue を対象にする

- **WHEN** `example` の issue 140 のカード詳細を開いた `Model` に `L` を与え、返ったコマンドを実行して得たメッセージを `Update` に渡す
- **THEN** 画面はラベル一覧で、書き先は `org/app` の issue 140（issue である）、元の集合は空である

#### Scenario: ラベルが 0 件なら画面を変えずステータスに出す

- **WHEN** `labels.json` が空の配列の fixture ディレクトリを読む `Fake` を `client` にして `L` を与え、返ったコマンドを実行して得たメッセージを `Update` に渡し、`View` から ANSI エスケープを除いて読む
- **THEN** 画面はキューのままで、フッタに `ラベルがありません` が含まれる

#### Scenario: 0 件のリポジトリで L を 2 回押しても一覧は開かない

- **WHEN** 上の手順の後に、同じ `Model` にもう一度 `L` を与える
- **THEN** コマンドは返らず、画面はキューのままで、フッタに `ラベルがありません` が含まれ、`Fake.Calls` の `ListLabels` は 1 件のままである（キャッシュ経路でも 0 件の一覧を開かない）

#### Scenario: 取得に失敗したら赤で出る

- **WHEN** `*gh.Fake` を埋め込んで `ListLabels` だけがエラー `gh label list -R org/app: exit 1: HTTP 403` を返す型を `client` にして `L` を与え、返ったコマンドを実行して得たメッセージを `Update` に渡し、`View` から ANSI エスケープを除いて読む
- **THEN** 画面はキューのままで、フッタに `org/app のラベル一覧を取得できません:` と `HTTP 403` が含まれる

#### Scenario: 取得中に画面が変わったら一覧を開かない

- **WHEN** `L` を与えた直後（返ったコマンドを実行する前）に `?` を与えてヘルプ画面に移り、そのうえで取得のメッセージを `Update` に渡し、`View` から ANSI エスケープを除いて読む
- **THEN** 画面はヘルプのままで、フッタに `org/app のラベル一覧の表示を中止しました（画面が変わりました）` が含まれる

#### Scenario: 書き込み中の L は何もしない

- **WHEN** 今やるタブの issue 108 の Card を選んだ `Model` に `t` を与えた直後（返ったコマンドを実行する前）に `L` を与える
- **THEN** コマンドは返らず、画面はキューのままである

#### Scenario: 0 行のタブと確認画面とヘルプ画面と URL 一覧で L は何もしない

- **WHEN** `example` の `Result` を渡して異常タブ（0 行）に切り替えた `Model` に `L` を与え、別に s10 の手順で blocked-by の確認画面に移った `Model` に `L` を与え、別に `?` でヘルプ画面を開いた `Model` に `L` を与え、別に `u` で URL 一覧を開いた `Model` に `L` を与える
- **THEN** どれもコマンドは返らず、画面は変わらず、`Fake.Calls` は空である

#### Scenario: 小文字の l は何もしない

- **WHEN** `example` の `Result` を渡した `Model`（キュー画面）に `l` を与え、別にカード詳細を開いた `Model` に `l` を与える
- **THEN** どちらもコマンドは返らず、画面は変わらない（`l` は s17 のカンバンの列移動の予約のままである）

#### Scenario: 取得のたびに一覧を取り直す

- **WHEN** `L` で一覧を開いて `Esc` で戻った後に、取得完了のメッセージを `Update` に渡し、もう一度 `L` を与える
- **THEN** コマンドが返り、`View` のフッタに `org/app のラベル一覧を取得中` が含まれる（`Fake.Calls` の `ListLabels` は 2 件になる）

#### Scenario: 取得の失敗では一覧を捨てない

- **WHEN** 同じ手順で、取得失敗のメッセージを `Update` に渡し、もう一度 `L` を与える
- **THEN** コマンドは返らず、画面はすぐラベル一覧になり、`Fake.Calls` の `ListLabels` は 1 件のままである
