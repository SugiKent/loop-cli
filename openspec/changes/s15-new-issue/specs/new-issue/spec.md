## Purpose

キューを見ている人が、その場で新しい issue を起こせるようにする。作成先のリポジトリは画面が見せている対象から決まり、人はタイトルと本文を書くことだけに集中する。

## ADDED Requirements

### Requirement: n は画面の対象のリポジトリを作成先にしてエディタを開く
`Model` の `Update` は `n` を画面の状態ごとに MUST 次のとおり扱う。作成先のリポジトリ名を決め、下書きを空文字列にして `Editor("")` が返すコマンドをそのまま（他のコマンドとまとめずに）返す。リポジトリは人に選ばせない。
- キュー画面: 選択行の主体（s08 `queue-screen` の `Subject`）のリポジトリ。選択行が無ければ画面を変えず、コマンドも返さず、フッタの右側に `新規作成の対象がありません` を出す
- カード詳細画面: 詳細の対象の `Card.Issue.Repo`
- PR 詳細画面: 詳細の対象の PR の `Repo`
- 回答の確認画面 / merge の確認画面 / ヘルプ画面 / URL 一覧画面 / 作成の確認画面: 何もしない（`n` はこれらの画面のキーの振り分けより後ろで扱う）

作成先が主体の種類（issue か PR か）で変わることは無い。PR の行を選んで `n` を押せば、その PR のリポジトリに issue が作られる。
書き込み（回答の投稿・ラベル切り替え・merge・issue の作成）の結果を待っている間は `n` を無視する（s11 `todo-toggle`「書き込み中は t と a を受け付けない」の MODIFIED）。
エディタが動いている間、`Model` はキー入力を受けない（s10 `answer-question`「a は画面の対象を決めて回答テンプレートを入れたエディタを開く」と同じ仕組み）。

#### Scenario: キュー画面で n を押すと選択行のリポジトリが作成先になる
- **WHEN** `example` の `Result` を渡し、渡された `initial` を記録するスタブ `Editor` で `New` した `Model` に `n` を与える。今やるタブの行は issue 108 と PR 131 の Card で、そのリポジトリは `org/app` である
- **THEN** コマンドが返り、それを実行するとスタブは `initial` として空文字列を受け取り、`Model` が保持する作成先は `org/app` である

#### Scenario: 0 行のタブで n は対象が無いと出す
- **WHEN** `example` の `Result` を渡して異常タブ（0 行）に切り替えた `Model` に `n` を与え、`View` から ANSI エスケープを除いて読む
- **THEN** コマンドは返らず、画面はキューのままで、フッタに `新規作成の対象がありません` が含まれ、スタブ `Editor` は呼ばれない

#### Scenario: カード詳細でも PR 詳細でも作成先は同じリポジトリになる
- **WHEN** `example` の issue 108 のカード詳細を開いた `Model` に `n` を与え、別に同じカードから `Enter` で PR 131 の PR 詳細を開いた `Model` に `n` を与える
- **THEN** どちらもコマンドが返り、作成先はどちらも `org/app` で、スタブに渡る `initial` はどちらも空文字列である

#### Scenario: ヘルプ画面と URL 一覧画面の n は何もしない
- **WHEN** `example` の `Result` を渡した `Model` に `?` を与えてヘルプ画面で `n` を与え、別に `u` を与えて URL 一覧画面で `n` を与える
- **THEN** どちらもコマンドは返らず、画面はそれぞれヘルプ画面と URL 一覧画面のままで、スタブ `Editor` は呼ばれない

### Requirement: 編集結果を検査して作成の確認画面に移る
`Update` は `n` で始めた編集の完了を MUST 次の順で扱う。分割と検査は `new-issue-action` と同じ関数（`action.SplitNewIssue`、`action.HasRoutineMarker`）を使い、`internal/ui` に別の判定を持たない。編集の完了が `a` と `n` のどちらで始まったものかは `Model` が覚えており、`a` で始めた編集は s10 `answer-question`「編集結果を検査してから投稿する」が扱う。
1. エラーを持つ: フッタの右側に `エディタ: <エラー文字列>` を赤で出し、作成しない。画面は `n` を押した画面のまま
2. 分割したタイトルが空: フッタの右側に `作成を中止しました（タイトルが空）` を出し、作成しない
3. 分割した本文が空: フッタの右側に `作成を中止しました（本文が空）` を出し、作成しない
4. それ以外: 下書き（編集後のテキストそのもの）とタイトルと本文を保持し、作成の確認画面に移る。`action.HasRoutineMarker` がタイトルか本文に対して真なら、確認画面に作成の選択肢を出さない（不変条件 7）

タイトルだけ、または本文だけの下書きを作成しないのは、タイトルの無い issue がキューの表で見分けられず、本文の無い issue が routine の読む材料を持たないためである。

#### Scenario: タイトルと本文がそろえば確認画面に移る
- **WHEN** 固定文字列 `キュー画面の色を見直す\n\n種別の色が背景色と競合している。` を返すスタブ `Editor` で `New` し、`example` の `Result` を渡した `Model` に `n` を与え、返ったコマンドを実行して得たメッセージを `Update` に渡し、`View` から ANSI エスケープを除いて読む
- **THEN** 画面は作成の確認画面で、`新規 issue の確認: org/app` の行、`タイトル: キュー画面の色を見直す` の行、本文の `種別の色が背景色と競合している。` の行があり、`Fake.Calls` は空である

#### Scenario: タイトルが空なら作成しない
- **WHEN** スタブが `\n本文だけ書いた` を返す状態で同じ手順を行い、`View` から ANSI エスケープを除いて読む
- **THEN** 編集完了のメッセージに対してコマンドは返らず、画面はキューのままで、フッタに `作成を中止しました（タイトルが空）` が含まれ、`Fake.Calls` は空である

#### Scenario: 本文が空なら作成しない
- **WHEN** スタブが `タイトルだけ書いた` を返す状態で同じ手順を行い、`View` から ANSI エスケープを除いて読む
- **THEN** コマンドは返らず、フッタに `作成を中止しました（本文が空）` が含まれ、`Fake.Calls` は空である

#### Scenario: マーカーを含む下書きは作成の選択肢の無い確認画面になる
- **WHEN** スタブが `タイトル\n<!-- routine -->\n本文` を返す状態で同じ手順を行い、`View` から ANSI エスケープを除いて読む
- **THEN** 画面は作成の確認画面で、`<!-- routine -->` を含む下書きでは作成できません の行があり、フッタに `e 編集に戻る` と `Esc 中止` があって `y 作成` は無く、`Fake.Calls` は空である

#### Scenario: エディタの失敗は赤で出て作成されない
- **WHEN** スタブがエラー `exit status 1` を返す状態で同じ手順を行い、`View` から ANSI エスケープを除いて読む
- **THEN** コマンドは返らず、`Fake.Calls` は空で、フッタに `エディタ: exit status 1` が含まれ、画面はキューのままである

#### Scenario: a で始めた編集は回答の経路のまま
- **WHEN** スタブが `Q1: A` を返す状態で、主体が PR 131 の Card を選んだ `Model` に `a` を与え、返ったコマンドを実行して得たメッセージを `Update` に渡し、さらに返ったコマンドを実行して得たメッセージを `Update` に渡す
- **THEN** `Fake.Calls` はちょうど 1 件で `Method` が `CommentPR` であり、`Method` が `CreateIssue` の要素は無い

### Requirement: 作成の確認画面は作成先と下書きを出し、y で作成して Esc で中止する
`Model` は画面の状態として、s14 までの 7 つに加えて 作成の確認 を MUST 持ち、確認画面に移るときは戻り先（`n` を押した画面）と作成先のリポジトリ名と下書きとタイトルと本文を保持する。確認画面の `View` は、端末の幅と高さの全体を使い、上から MUST 次の順で描く。
1. `新規 issue の確認: <作成先のリポジトリ名>`
2. `タイトル: <タイトル>`
3. マーカーがあるときだけ `<!-- routine --> を含む下書きでは作成できません（TUI からの書き込みは人の発言でなければなりません）`
4. 区切り線（端末幅ぶんの `─`）
5. 本文
6. フッタ

収まらない分は残りの高さで切り（スクロールしない。s10 / s14 の確認画面と同じ）、各行は端末の幅で切り詰め、フッタは常に出す。フッタの左はマーカーが無ければ `y 作成  e 編集に戻る  Esc 中止  q 終了`、あれば `e 編集に戻る  Esc 中止  q 終了`。右は s08 と同じステータス。
確認画面のキーは MUST 次のとおり。
- `y`: マーカーが無いときだけ、作成のコマンド（Requirement「作成の結果をステータスに出し、再取得しない」）を返して戻り先の画面に戻る。マーカーがあれば何もしない
- `e`: 下書き（編集後のテキストそのもの。タイトルと本文に分ける前の形）を `initial` にして `Editor` を呼び、そのコマンドを返す。画面は戻り先に戻す（編集結果は Requirement「編集結果を検査して作成の確認画面に移る」の手順にもう一度かかる）
- `Esc`: 作成せず戻り先の画面に戻り、フッタの右側に `作成を中止しました` を出す
- `q` / `Ctrl+C`: 終了コマンドを返す
- 他のキー（`a` / `t` / `m` / `o` / `?` / `u` / `n` を含む）: 何もしない

確認画面で取得完了のメッセージ（s08 `fetchedMsg`）が届いたら、`Cards` と最終更新時刻は s08 の規則どおり更新し、作成先と下書きは変えない。確認画面を読んでいる間に自動更新で選択行が動いても、作成先は `n` を押した時点のリポジトリのままである。詳細画面へ戻るときは本文領域の内容と寸法を作り直す（s12 `help-screen` の戻り方と同じ）。

#### Scenario: y で issue が作られる
- **WHEN** 1 つ目の Requirement の手順で作成の確認画面に移った `Model` に `y` を与え、返ったコマンドを実行して得たメッセージを `Update` に渡す
- **THEN** `Fake.Calls` は 1 件で `Method` が `CreateIssue`、`Repo` が `org/app`、`Title` が `キュー画面の色を見直す`、`Body` が `種別の色が背景色と競合している。` であり、画面はキューである

#### Scenario: e で下書き全体を入れたエディタが再び開く
- **WHEN** 同じ確認画面の `Model` に `e` を与え、返ったコマンドを実行する
- **THEN** スタブは `initial` として `キュー画面の色を見直す\n\n種別の色が背景色と競合している。` を受け取り、`Fake.Calls` は空である

#### Scenario: Esc で中止する
- **WHEN** 同じ確認画面の `Model` に `Esc` を与え、`View` から ANSI エスケープを除いて読む
- **THEN** 画面はキューで、`Fake.Calls` は空で、フッタに `作成を中止しました` が含まれる

#### Scenario: マーカーの確認画面で y は何もしない
- **WHEN** スタブが `タイトル\n<!-- routine -->\n本文` を返して移った確認画面の `Model` に `y` を与える
- **THEN** コマンドは返らず、画面は確認画面のままで、`Fake.Calls` は空である

#### Scenario: 詳細画面から入った確認画面は詳細画面に戻る
- **WHEN** `example` の issue 108 のカード詳細で `n` を押し、スタブが `タイトル\n\n本文` を返して移った確認画面の `Model` に `Esc` を与える
- **THEN** 画面はカード詳細で、詳細の対象は issue 108 の Card のままである

#### Scenario: 確認中に取得が完了しても作成先は変わらない
- **WHEN** 同じ確認画面（キュー画面から入ったもの）の `Model` に、issue 108 の Card を含まない `Result` を取得完了として渡し、`y` を与えて返ったコマンドを実行する
- **THEN** 画面は確認画面のまま取得が反映され、`Fake.Calls` の `CreateIssue` の `Repo` は `org/app` である

#### Scenario: 確認画面で他のキーは何もしない
- **WHEN** 同じ確認画面の `Model` に `a`、`t`、`m`、`o`、`?`、`u`、`n` を 1 つずつ与える
- **THEN** どのキーでもコマンドは返らず、画面は確認画面のままで、`Fake.Calls` は空である

### Requirement: 作成の結果をステータスに出し、再取得しない
作成のコマンドは `action.CreateIssue` を作成先とタイトルと本文で呼び（`ctx` は 30 秒のタイムアウト付き。s10 / s14 と同じ）、その結果（作成先・URL・エラー）を運ぶ `internal/ui` 内のメッセージを返す。`Model` は `gh` を直接呼ばず、作成は必ずコマンド（別ゴルーチン）で MUST 行う。
- 作成中: フッタの右側に `<作成先> に issue を作成中` を出す。この間の `a` / `t` / `m` / `n` は何もしない
- 成功: フッタの右側に `<作成先> に issue を作成しました: <URL>` を出す。URL は `action.CreateIssue` が返した文字列をそのまま出す（人はこれをブラウザに貼って開く）
- 失敗: フッタの右側に `<作成先> の issue 作成に失敗: <エラー文字列>` を赤で出す

作成の成否にかかわらず、`Cards` と最終更新時刻を変えず、取得のコマンドを返さない（作った issue は次の `R` か自動更新で現れる。書き込み後の対象 1 件再取得は s18 が担当する）。ラベルは触らない。このステータスは次の取得が始まったとき、または次に `a` / `t` / `n` を押したときに消える。

#### Scenario: 作成の成功と URL がフッタに出る
- **WHEN** Requirement「作成の確認画面は作成先と下書きを出し、y で作成して Esc で中止する」の 1 つ目の Scenario の手順を行い、`View` から ANSI エスケープを除いて読む
- **THEN** フッタに `org/app に issue を作成しました: https://github.com/org/app/issues/0` が含まれ、`Cards` は変わらず、今やるタブに issue 108 の行が残る

#### Scenario: 作成中は作成中の表示で a と t と m と n は効かない
- **WHEN** 同じ手順で `y` を与えて作成のコマンドが返った直後（コマンドを実行する前）に `View` を読み、続けて `a`、`t`、`m`、`n` を 1 つずつ与える
- **THEN** フッタに `org/app に issue を作成中` が含まれ、どのキーでもコマンドは返らず、`Fake.Calls` は空である

#### Scenario: 作成の失敗は赤で出る
- **WHEN** `*gh.Fake` を埋め込んで `CreateIssue` だけがエラー `gh issue create -R org/app: exit 1: HTTP 403` を返す型を `client` にして同じ手順を行い、`View` から ANSI エスケープを除いて読む
- **THEN** フッタに `org/app の issue 作成に失敗:` と `HTTP 403` が含まれ、`Cards` は変わらない

#### Scenario: 作成でラベルは書かない
- **WHEN** 同じ手順で作成を完了した後に `Fake.Calls` を見る
- **THEN** `Method` が `AddLabel` または `RemoveLabel` の要素は無く、`CreateIssue` がちょうど 1 件である
