issue: #38

## Why

`a` で開くエディタに入るのは `Q1: A\nQ2: B` の記号だけで、質問文と選択肢は画面（カード詳細の blocked-by 要約、
PR 詳細のコメント）にしか無い。`ExternalEditor` は Bubble Tea の外部プロセス実行で端末を明け渡し、
`answer-question`「エディタが動いている間、`Model` はキー入力を受けない」と定めてあるので、
**`A` が何の案だったかを確かめるにはエディタを閉じるしかない**。記号だけのテンプレートは、推奨をそのまま採るとき以外は
役に立たない。

さらに調べると、**そのテンプレートが実際には 1 件も作られていない**。`model.ParseQuestions` が見るのは
`## Q<n>.` の見出しと `- 選択肢 A（推奨）: …` の行だけ（`internal/model/parse.go:28-29`）だが、
`routine-propose` が PR に投稿する質問コメントは `### Q<n>.` の見出しと `- **選択肢 A（推奨）**: …` の行である
（上流 skill の書式。実物は PR #37 のコメント 5637653944）。この本文を `ParseQuestions` に渡すと**質問 0 件**になる
（手元で実行して確認）。つまり局面 A（優先度 1。issue #38 の動機そのもの）では、いまエディタが白紙で開く。
issue の `blocked-by: human` コメントも見出し形式が固定でないので同じく白紙になる。

引用を足すだけでは、この白紙は白紙のままである。パースの書式と、エディタに入れる文字の両方を直す。

## What Changes

- `model.ParseQuestions` が読む書式を、実際に届く質問コメントに合わせる
  - 見出し行の `#` は 1 つ以上を許す（`### Q1.` が読めるようになる。今は `##` で始まる行しか読まない）
  - 選択肢行の Markdown 強調 `**` を読み飛ばす（`- **選択肢 A（推奨）**: …` と `- **選択肢 A**（推奨）: …` が読める）
  - これだけで、いま 0 件になっている実物の質問コメントから `Q1: A` の回答行が作られ、カード詳細の blocked-by 要約にも
    質問と選択肢が出る（`internal/ui/detail.go:311-322` が同じ関数を使っている）
- `action.AnswerTemplate` が、回答行の前に**質問コメントの引用**を置く。1 行を `> <行>`、空行を `>` の
  1 文字にした引用ブロックのあと、空行 1 行を挟んで `Q<n>: <記号>` の行を並べる
- 引用する**コメントの選び方**を、本文の中身で決める。`comments` を末尾から先頭へ見て、最初に見つかる
  「人への問い」の routine コメント（質問の見出しを持つ、または `blocked-by:` 行を持つ）を選ぶ。最新のコメントに
  限らないので、人の返信・`started:` / `session:` の作業印・`## PR リスク評価` の評価コメントを飛び越えて問いに届く
  （PR #41 のコメントで確定）。回答行も同じコメントから作る
- 引用する**範囲**を、パースできた行だけに絞らず「質問が始まった行から終わった行まで」にする（同）。
  範囲の中の説明文・表・`- 依存:` の行はそのまま引用に入る
  - 始まり: 最初の質問見出しの行。見出しを持たないコメント（issue の `blocked-by: human`）では、マーカー行と
    `blocked-by:` / `unblock-when:` の行を飛ばした後の最初の非空行
  - 終わり: 本文の末尾から、空行・区切り線だけの行・`_…_` の署名行（`_Generated by [Claude Code](…)_`）を
    落としていって最初に残る行
- 引用に入れない行を決める
  - routine マーカーだけの行は落とす（`internal/ui/preview.go:98-109` の `stripMarkers` と同じ規則）。
    行の途中にあるマーカーは `[routine マーカー]` に置き換えて残す。マーカーを含む本文は投稿できない
    （`answer-action`「routine マーカーを含む本文は投稿しない」）ので、テンプレートから確実に消す必要がある
  - `blocked-by:` 行と `unblock-when:` 行は落とす。人が読みたいのは散文と選択肢であり、正本の宣言行ではない
    （画面側の `questionLines` も同じ 2 行を落としている）
- **引用行と空行だけの本文を投稿しない。** 空の本文を拒む既存の規則（`answer-action`「空の本文は投稿しない」の
  「中身の無い回答が『回答済み』になるのを防ぐ」）を引用にも当てる。引用だけのテンプレートを開いてそのまま閉じた
  下書きが、dispatcher に「人が答えた」と読まれて worker が推奨案で進む経路を作らないため
- 引用は**そのまま投稿される**。投稿前に落とす処理は持たない（PR #41 のコメントで確定）

## 確定した判断

- **パースの拡張をこの change に含める。** 別 change に切り出すと #38 は先行 change の archive を待つ
  `blocked-by: change …` になり、しかも切り出し先の issue を起こすことになる（routine は残作業の起票を禁じている）。
  拡張の実体は正規表現 2 本で、`AnswerTemplate` と同じ「質問を読む」経路にある
- **引用は本文を写すだけにし、質問の構造から組み立て直さない。** 写す方式なら前置きの 1 行
  （「`Q1: A` の形で返してください」）、`- 依存: なし` の行、`blocked-by: human` コメントの散文が残る。
  パースした `Question` から行を作り直すと、パースできた質問しか復元できない
- **引用にマーカーを残せない。** `HasRoutineMarker` は本文のどこにあってもマーカーを検出し
  （`internal/action/action.go:36-40`）、検出された下書きは投稿の選択肢が無い確認画面に入る
  （`answer-question`「編集結果を検査してから投稿する」手順 3）。マーカーが残ると**回答を 1 件も投稿できなくなる**
- **マーカーは行ごと落とすだけにしない。** 行の途中にマーカーを含む質問行（`## Q1. 先頭に <!-- routine --> を入れるか`）を
  行ごと落とすと、質問文が消えたまま回答行 `Q1: A` だけが残り、**白紙より悪い「完成して見える下書き」**になる。
  マーカーだけの行は落とし、行の途中のマーカーは置き換えて残す
- **引用から `blocked-by:` と `unblock-when:` を落とす。** `docs/domain/issue-driven-sdd/human-turn-signals.md` の
  不変条件 8 は「人が引用しただけで判定が変わる」ことを危険として挙げている。TUI と dispatcher は行頭の `>` を
  吸収しない（`answer-action`「`> blocked-by: human` は検出しない」）が、正本の判定は LLM が散文の規約に従って行うので、
  引用した宣言行を正本と読む余地を既定の動作として作らない
- **引用行と空行だけの下書きは投稿しない。** `internal/ui/answer.go:100-109` の検査は「前後の空白を除いて空」でしか
  中止しないので、引用だけのテンプレートを開いてそのまま閉じると即座に投稿される。局面 B でこれが起きると、
  `routine-dispatch` の `unblock-when: comment`（正本より後に人のコメントがあれば解ける）に当たって worker が
  推奨案で進む。いまは局面 B のテンプレートが空なので同じ誤爆は何も起こさないので、安全側の既定を保つ
- **対象は最新のコメントに限らず、中身で選ぶ**（PR #41 のコメントで確定）。`comments` を末尾から先頭へ見て、
  最初に見つかる「人への問い」の routine コメント（質問の見出しを持つ、または `blocked-by:` 行を持つ）を選び、
  引用と回答行の両方をそこから作る。位置で選ばないので、人の返信や作業印のコメントを飛び越えて問いに届く。
  回答行の元も同じコメントに揃えるのは、引用と回答行が別のコメントから来ると、どの問いに答えているのかが
  下書きの中で食い違うからである
- **引用する範囲は「質問が始まった行から終わった行まで」**（同）。パースできた見出しと選択肢だけに絞らないので、
  `**何の話か**:` の説明文・コントラスト比の表・`- 依存: なし` の行も引用に入る。始まりは最初の質問見出しの行
  （見出しを持たないコメントでは、マーカー行と `blocked-by:` / `unblock-when:` の行を飛ばした後の最初の非空行）、
  終わりは末尾から空行・区切り線・`_…_` の署名行を落とした位置とする
- **引用は回答行の前に置く。** 投稿したコメントが GitHub 上で「引用された問い → 回答」の順に読める。
  エディタのカーソルは 1 行目（引用の先頭）に立つので、回答行まで人が移動する
- **`internal/ui` の描画と画面遷移は変えない。** 変わるのはエディタに渡る文字列と、空とみなす範囲だけである
- **`n`（新しい issue）の下書きは変えない。** 案内 2 行を区切りに使う別の経路である（`internal/action/newissue.go:14-30`）

## 未確定の判断

### Q1. 引用の始まりを、質問見出しからにするか、コメントの前置きからにするか
質問コメントは前置き（`未確定の判断が 3 件あります。Q1: A の形で返してください。…`）で始まり、区切り線を挟んで
最初の質問見出しへ進む（PR #37 の実物）。「明らかに質問が始まったところ」をどちらに取るかで、引用の頭が変わる。
- 選択肢 A（推奨）: 最初の質問見出しの行から引用する。前置きが伝えるのは答え方の案内で、その形
  （`Q1: A`）は引用の下に並ぶ回答行そのものが示している。エディタの 1 行目が `> ### Q1. …` になるので、
  開いた瞬間に最初の問いが目に入る
- 選択肢 B: マーカー行の次から、つまりコメントの前置きを含めて引用する。答え方の案内と「このまま merge した場合は
  推奨案で進みます」の一文も一緒に読める。代わりに、人は質問が始まるまでに数行を読み進めることになる
- 依存: なし
