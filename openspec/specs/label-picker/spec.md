# label-picker Specification

## Purpose
`L` で対象リポジトリのラベル一覧を画面に出し、印を切り替えて選んだ変更を 1 回の書き込みでまとめて反映する経路を定める。対象は issue でも PR でもよく、`t`（`stage:todo` 専用）では触れないラベルをここから付け外しする。

## Requirements

### Requirement: L は画面の対象のラベル一覧画面を開く

`Model` は画面の状態として、s22 までの 7 つ（キュー / カード詳細 / PR 詳細 / 回答の確認 / merge の確認 / ヘルプ / URL 一覧）に加えて **ラベル一覧** を MUST 持つ。`Update` は `L`（`Shift` + `l` の大文字。小文字の `l` はカンバンの列移動として s17 に予約されたままで、この change では何もしない）を画面の状態ごとに MUST 次のとおり扱う。対象は `a`（s10 `answer-question`）と同じ規則で決まる。

- キュー画面: 選択行の主体（s08 `Subject`）。選択行が無ければ何もしない
- カード詳細画面: 詳細の対象の `Card.Issue`
- PR 詳細画面: 詳細の対象の選択中の PR
- 回答の確認画面 / merge の確認画面 / ヘルプ画面 / URL 一覧画面: 何もしない（それぞれの画面の分岐が先に処理する）

書き込み中（s11 `todo-toggle`「書き込み中は t と a を受け付けない」の状態）なら何もしない。

対象が決まったら、`L` を押した時点で MUST 次の 3 つを写し取る。一覧を出している間に取得完了（s08）で `Cards` が入れ替わっても、これらは変えない。

1. 書き先（`Repo` / `Number` / issue か PR かの区別。s14 `merge-pr` が確認画面の対象を押した時点で固定するのと同じ。自動更新は画面の状態を見ないので、一覧を出している間にも走る）
2. **対象に付いているラベル名の集合**（`Card.Issue.Labels` / `PR.Labels`。最後の取得の時点の値）。以降この写しを「元の集合」と呼び、行の印・見出しの変更件数・「変更が無い」の判定はすべてこれを基準にする
3. 戻り先（`L` を押した画面）

続けてラベルの一覧を用意する。`Model` はリポジトリ名をキーにしたラベルの表を持ち、経路は 2 つに分かれる。

- **表にある**: コマンドを返さず、下の「一覧を開く判定」に進む。書き込み中フラグは立てない
- **表に無い**: `GHClient.ListLabels` を呼ぶコマンドを返し、書き込み中フラグを立て、フッタの右側のステータスに `<Repo> のラベル一覧を取得中` を出す。結果を受け取ったら書き込み中フラグを下ろし、失敗なら画面を変えずフッタに `<Repo> のラベル一覧を取得できません: <エラー文字列>` を赤で出す（表には何も入れない）。成功したら表に入れて「一覧を開く判定」に進む

**一覧を開く判定**（2 つの経路が合流する 1 か所。キャッシュの有無で結果が変わってはならない）。

- ラベルが 0 件: 画面を変えず、フッタに `ラベルがありません` を通常の色で出す（s22 の `URL がありません` と同型）
- 1 件以上で、画面が `L` を押した時点と同じ: ラベル一覧画面に移り、選択位置を先頭にする
- 1 件以上で、画面が変わっている: 画面は変えず、フッタに `<Repo> のラベル一覧の表示を中止しました（画面が変わりました）` を通常の色で出す（`openspec/specs/merge-pr/spec.md` の「取り直しの間に画面が変わったら確認画面に移らない」と同じ理由。取得中も `o` / `?` / `u` / `Esc` は動くので、開いたヘルプ画面や URL 一覧をあとから届いた一覧が踏み潰さないようにする）。キャッシュ経路では画面が変わる余地が無いのでこの枝に入らない

表は取得（初回・`R`（s12 `manual-refresh`）・自動更新（s13））が成功するたびに MUST 捨てる。次に `L` を押したときに取り直すので、他の経路でラベルを作っても、次の更新のあとの `L` には出る。s30 で運用方式を毎回の取得で判定し直すようになり、方式は変わるのにこの一覧だけが起動時のまま古く残る状態を作らないための規則である。取得が失敗したときは捨てない（前回の結果を維持する D-002 と同じ扱いで、取り直せない状況で一覧を空にしない）。`ListLabels` は 1000 件で切れるが、切れていることは画面に出さない。

### Requirement: 一覧画面は Space で印を切り替え Enter で送信し Esc で捨てる

ラベル一覧画面は、対象について「送信後にこうなっていてほしいラベル名の集合」を MUST 持つ。初期値は Requirement「L は画面の対象のラベル一覧画面を開く」で写し取った**元の集合**である。

`Model` の `Update` は、画面の状態がラベル一覧のとき、キー入力を MUST 次のとおり扱う。

- `j` / `↓`: 選択を 1 つ下へ。末尾では動かない（循環しない）
- `k` / `↑`: 選択を 1 つ上へ。先頭では動かない
- `Space`: 選択中の行のラベル名を集合に足す（無ければ）か、集合から外す（あれば）。`gh` は呼ばず、コマンドも返さない
- `Enter`: 送信する（Requirement「送信は元の集合との差分を作り 1 回で書き込む」）
- `Esc`: 集合を捨てて戻り先の画面に戻る。戻り先の状態（タブ・選択行・詳細の対象・選択中の PR・展開状態・スクロール位置）は開く前のまま。戻り先がカード詳細 / PR 詳細なら本文領域の内容と寸法を作り直す（s12 `help-screen` / s22 `url-picker` と同じ理由）
- `q` / `Ctrl+C`: 終了コマンドを返す
- 他のキー（`L` / `l` / `a` / `t` / `m` / `o` / `?` / `u` / `R` / `x` / `g` / `1`〜`4` / `Tab` を含む）: 何もしない。`L` も含めるので、一覧を出したまま `L` を押しても戻り先は上書きされない

`Update` はラベル一覧画面の振り分けを **`u` の判定よりも前**（URL 一覧画面の振り分けの直後、`u` のハンドラの前）に置き、`L` のハンドラを `u` のハンドラの後ろ・`a` の判定の前に置く。ラベル一覧画面の分岐を `u` より後ろに置くと、一覧の上で `u` を押したときに URL 一覧が開いて変更予定が失われる。`a` / `t` / `m` / `o` / `?` より後ろに置くと、一覧の裏にある対象に対して回答・ラベル書き込み・ブラウザ起動が起きる。

一覧を出している間に取得完了（s08）・投稿結果（s10）・切り替え結果（s11）・ブラウザで開く結果（s12）・merge の結果（s14）のメッセージが届いたら、各 change の規則どおりに処理し、画面はラベル一覧のままにする。取得完了で `Cards` が入れ替わっても、元の集合と書き先は写しなので変わらない。端末サイズの変更も受け取り、一覧の幅と高さに反映する。

#### Scenario: j と k で選択が動く

- **WHEN** ラベルが 3 件ある fixture ディレクトリでラベル一覧を開いた `Model` に、`j` を 3 回、`k` を 1 回与える
- **THEN** 選択位置は順に 1、2、2、1 になる

#### Scenario: Space は印を切り替えるだけで gh を呼ばない

- **WHEN** ラベル一覧を開いた `Model` に `Space` を 1 回与える
- **THEN** コマンドは返らず、`Fake.Calls` に `ListLabels` 以外は無く、画面はラベル一覧のままである

#### Scenario: 一覧を出している間の取得完了で印も書き先も動かない

- **WHEN** `Labels` が `wip` の issue 150 を今やるタブに持つ手書きの Card から `L` でラベル一覧を開き、`wip` の行で `Space` を 1 回与えた後に、**同じ issue 150 の `Labels` を空に、選択行を別の Card に差し替えた** `Result` を取得完了として `Update` に渡し、続けて `Enter` を与えて返ったコマンドを実行する
- **THEN** 画面はラベル一覧のまま取得完了を受け、`Fake.Calls` の書き込みは `Number` が 150 の `EditIssueLabels` 1 件で、`RemoveLabels` は `["wip"]` である（書き先も元の集合も `L` を押した時点の写しのままである）

#### Scenario: Esc は変更予定を捨てる

- **WHEN** ラベル一覧を開いて `Space` を 1 回与えた `Model` に `Esc` を与え、もう一度 `L` を与えて一覧を開き直す
- **THEN** `Esc` の後の画面は戻り先で、`Fake.Calls` に `EditIssueLabels` / `EditPRLabels` は無く、開き直した一覧の印は元の集合どおりに戻っている

#### Scenario: 一覧画面で他のキーは何もしない

- **WHEN** ラベル一覧を開いた `Model` に `L`、`l`、`a`、`t`、`m`、`o`、`?`、`u`、`R`、`x`、`g`、`2` を 1 つずつ与える
- **THEN** どのキーでもコマンドは返らず、画面はラベル一覧のまま、選択位置と戻り先と変更予定は変わらず、`Fake.Calls` に `ListLabels` 以外は無く、スタブ `Editor` は呼ばれない

#### Scenario: 一覧画面でも q で終了する

- **WHEN** ラベル一覧を開いた `Model` に `q` を与える
- **THEN** 終了コマンドが返る

### Requirement: 一覧画面は見出しとラベルの行とフッタを出す

画面の状態がラベル一覧のとき、`View` は端末の幅と高さの全体を使い、上から MUST 次の順で描く。

1. 見出し `ラベルを付け外し（変更 <n> 件）`。`<n>` は今の集合と**元の集合**の差分の件数
2. 空行
3. ラベルの行。1 行は `<選択の印><状態の印> <名前>  <説明>` で、選択の印は選択中の行が `▶ `、他の行が空白 2 列。名前と説明の間は空白 2 列で、説明が空のときは名前で終わる。状態の印は元の集合と今の集合の組み合わせで決まる次の 4 つ

| 印 | 元の集合 | 今の集合 | 意味 |
| --- | --- | --- | --- |
| `[x]` | あり | あり | 今付いていて、送信しても変わらない |
| `[ ]` | なし | なし | 今付いておらず、送信しても変わらない |
| `[+]` | なし | あり | 送信すると付く |
| `[-]` | あり | なし | 送信すると外れる |

4. 残りの高さは空行
5. 最終行はフッタ。左は `j/k 選択  Space 切替  Enter 送信  Esc 戻る  q 終了`、右は s08 と同じステータス（スピナー / エラー / 書き込みステータス）

各行は端末の幅で切り詰める。ラベルの件数が表示できる行数（端末の高さ − 見出し 1 行 − 空行 1 行 − フッタ 1 行）を超えるときは、選択中の行が必ず見えるように表示の開始位置をずらす（s22 `url-picker` の一覧と同じ規則）。一覧はスクロール位置を独立に持たず、選択位置だけを持つ。

各行の `<名前>` には、`queue-screen`「ラベル名は GitHub のラベル色を背景に、輝度で選んだ黒か白を文字にして描く」のとおり色を付ける。背景色に使うのは、この画面が `L` で取ったラベル一覧（`gh label list` の応答）が持つそのラベルの `color` であり、`internal/ui` の `Model` が持つリポジトリごとのラベル色の表は引かない（この画面は取得したてのラベル定義そのものを並べているので、同じ画面に新旧 2 つの色が混ざらないようにする）。選択の印・状態の印・説明・行の余白には色を付けず、名前の文字の範囲だけを塗る。色が空、または 16 進 6 桁として読めないラベルは色を付けずに描く。

#### Scenario: 一覧の行と見出しとフッタ

- **WHEN** `Labels` が `wip` の issue を持つ手書きの Card と、ラベルが `docs`（説明あり）と `wip`（説明あり）の 2 件の `labels.json` を持つ fixture ディレクトリでラベル一覧を開いた `Model`（幅 80・高さ 24）の `View` から ANSI エスケープを除いて読む
- **THEN** 1 行目は `ラベルを付け外し（変更 0 件）` で、`▶ [ ] docs` を含む行と `[x] wip` を含み `▶` を含まない行がこの順で含まれ、最終行に `j/k 選択`、`Space 切替`、`Enter 送信`、`Esc 戻る`、`q 終了` が含まれる

#### Scenario: 印は Space で変わり見出しの件数も動く

- **WHEN** 上の `Model` に `Space` を与えて `View` を読み、続けて `j` と `Space` を与えて `View` を読む
- **THEN** 1 回目は 1 行目が `ラベルを付け外し（変更 1 件）` で `[+] docs` を含む。2 回目は 1 行目が `ラベルを付け外し（変更 2 件）` で `[+] docs` と `[-] wip` の両方を含む

#### Scenario: 同じ行で Space を 2 回押すと印も件数も戻る

- **WHEN** 上の `Model` に `Space` を 2 回与えて `View` を読む
- **THEN** 1 行目は `ラベルを付け外し（変更 0 件）` で、`[ ] docs` を含み `[+] docs` を含まない

#### Scenario: 件数が高さを超えると選択に追従して表示がずれる

- **WHEN** ラベルを 30 件（`label-00` から `label-29`）持つ `labels.json` の fixture ディレクトリでラベル一覧を開いた `Model`（幅 80・高さ 10。表示できる行数は 7）で、`View` を読んでから `j` を 10 回与えて `View` を読む
- **THEN** 1 回目は `label-00` を含み `label-07` を含まない。2 回目は `label-10` を `▶` の行として含み、`label-00` を含まない

#### Scenario: 一覧の名前にラベル色が付く

- **WHEN** `docs`（色 `0075ca`）と `wip`（色 `fbca04`）の 2 件を持つ `labels.json` の fixture ディレクトリでラベル一覧を開いた `Model` の `View` を読む
- **THEN** `docs` は背景色 `0075ca` と白の文字色、`wip` は背景色 `fbca04` と黒の文字色で描かれ、`[ ]` / `[x]` の印と説明に色は付かず、ANSI エスケープを除いた各行はこの change の前と一致する

#### Scenario: 色を持たないラベルは色を付けずに描く

- **WHEN** `color` が空文字のラベル 1 件だけを持つ `labels.json` の fixture ディレクトリでラベル一覧を開いた `Model` の `View` を読む
- **THEN** その行は色を指定する ANSI エスケープを 1 つも含まない

### Requirement: 送信は元の集合との差分を作り 1 回で書き込む

`Enter` を受けたら `Model` は MUST 次を行う。

1. **画面を戻り先に戻す**（書き込みを始める前に一覧を閉じる。s14 `merge-pr` が `y` を受けた時点で確認画面を離れるのと同じ。一覧に留まると、送信中の `Space` / `Enter` で二重に送れてしまい、届いた結果があとから別の画面を引き剥がす）。戻り先がカード詳細 / PR 詳細なら本文領域の内容と寸法を作り直す
2. 今の集合と元の集合が同じなら、コマンドを返さずフッタに `<Repo> #<Number> のラベルに変更はありません` を出して終える（`gh` を 1 度も呼ばない）
3. 違えば書き込み中フラグを立て、フッタの右側に `<Repo> #<Number> のラベルを更新中` を出し、`internal/action` の関数を呼ぶコマンドを返す

関数は写し取った書き先（`action.Target`）と今の集合を受け取り、MUST 次の順で処理する。`ctx` は 30 秒のタイムアウト付き（s10 / s11 / s12 / s14 と同じ値）。

1. `Target.IsPR` が true なら `ViewPR`、false なら `ViewIssue` で対象の現在のラベルを読み直す（元の集合は最後の取得の時点のもので、その後に他の経路で変わっていると差分がずれるため。s11 の `ToggleTodo` が読み直すのと同じ理由）
2. 「今の集合にあって現在に無い」を付ける名前の並び、「現在にあって今の集合に無い」を外す名前の並びにする。どちらも名前の昇順に並べる（`gh` に渡す引数を決定的にするため）
3. どちらも空なら `gh` を呼ばずに戻る
4. `Target.IsPR` が true なら `EditPRLabels`、false なら `EditIssueLabels` を **ちょうど 1 回** 呼ぶ

読み直しの失敗と書き込みの失敗は、そのままエラーとして返す。ラベル名による拒否（`stage:*` を書かせないなどの判定）は行わない。人が一覧から明示的に選んだラベルはそのまま書く。

この経路は s11 の `ToggleTodo` を呼ばず、`ToggleTodo` もこの経路を使わない。`t` は `stage:todo` 固有の拒否（`ErrOtherStage` / `ErrMultipleStages` / `ErrBlocked`）と 1 ラベルずつの書き込みを保ったままにする。

#### Scenario: 付けると外すが 1 回の呼び出しにまとまる

- **WHEN** 元の集合が `wip` だけの issue 150 でラベル一覧を開き、`docs` を `[+]`、`wip` を `[-]` にしてから `Enter` を与え、返ったコマンドを実行する
- **THEN** `Fake.Calls` は `ListLabels` の後に `ViewIssue` と `EditIssueLabels` が 1 件ずつで、`EditIssueLabels` の `AddLabels` は `["docs"]`、`RemoveLabels` は `["wip"]` である

#### Scenario: Enter で先に一覧が閉じる

- **WHEN** 上の手順で `Enter` を与えた直後（返ったコマンドを実行する前）に `View` から ANSI エスケープを除いて読む
- **THEN** 画面は `L` を押した画面に戻っており、フッタに `org/app #150 のラベルを更新中` が含まれる

#### Scenario: 対象が PR なら EditPRLabels を呼ぶ

- **WHEN** PR 詳細でラベル一覧を開き、`docs` を `[+]` にして `Enter` を与え、返ったコマンドを実行する
- **THEN** `Fake.Calls` に `EditPRLabels` が 1 件あり、`Number` は選択中の PR の番号、`AddLabels` は `["docs"]` で、`EditIssueLabels` は無い

#### Scenario: 読み直した結果と一致していれば書き込まない

- **WHEN** `Labels` が空の issue 150 の手書きの Card（画面の Card）から一覧を開き、`ViewIssue` が `docs` の付いた issue 150 を返す fixture ディレクトリを `client` にして、`docs` を `[+]` にして `Enter` を与え、返ったコマンドを実行する
- **THEN** `Fake.Calls` に `ViewIssue` はあるが `EditIssueLabels` は無い（元の集合との差分は 1 件だが、読み直した現在のラベルとの差分は 0 件である）

#### Scenario: 変更が 0 件なら gh を 1 度も呼ばない

- **WHEN** 印を 1 つも切り替えずに `Enter` を与える
- **THEN** コマンドは返らず、`Fake.Calls` に `ViewIssue` と `EditIssueLabels` と `EditPRLabels` は無く、画面は戻り先である

#### Scenario: 段階ラベルも拒否されない

- **WHEN** `stage:propose` の付いた issue 108 でラベル一覧を開き、`stage:apply` を `[+]` にして `Enter` を与え、返ったコマンドを実行する
- **THEN** `Fake.Calls` に `EditIssueLabels` が 1 件あり、`AddLabels` は `["stage:apply"]` である（段階ラベルが 2 つある状態を人が作れる。`t` は以後この issue で `ErrMultipleStages` を返すので、戻すのも `L` から行う）

### Requirement: 送信の結果をステータスに出し、Cards を書き換えない

送信のコマンドは、付けた名前の並び・外した名前の並び・エラーを運ぶ `internal/ui` 内のメッセージを返す。`Model` はそのメッセージを受け取ったら書き込み中フラグを下ろし、フッタの右側（s10 / s11 / s12 / s14 と同じ 1 つのステータス）に MUST 次を出す。画面は送信の時点で戻り先に戻っているので、ここでは画面を変えない（届いた時点で利用者が別の画面に移っていても、その画面を奪わない）。

- 書き込んだ（エラー nil、どちらかの並びが空でない）: `<Repo> #<Number> のラベルを更新しました（<変更>）`。`<変更>` は付けた名前を `+<名前>`、外した名前を `-<名前>` として、付ける分・外す分の順に空白区切りで並べる（例 `+docs -wip`）
- 読み直しの結果、書くものが無かった（エラー nil、どちらの並びも空）: `<Repo> #<Number> のラベルに変更はありません`
- エラー（読み直しの失敗、書き込みの失敗のいずれも）: `<Repo> #<Number> のラベルを更新できません: <エラー文字列>` を赤で出す。`gh` は付けると外すを別の mutation として送るので、このエラーは「何も変わっていない」を意味しない（付けるほうだけ通っている場合がある）。実際の状態は次の取得で分かる

成否にかかわらず `Cards` と最終更新時刻と詳細の対象を変えず、Card の `Labels` も書き換えず、取得のコマンドを返さない（反映は s12 の `R` か s13 の自動更新による。s11 `todo-toggle` と同じ扱い）。このステータスは次の取得が始まったとき、または次に `a` / `t` を押したときに消える。

#### Scenario: 更新の結果がフッタに出る

- **WHEN** Requirement「送信は元の集合との差分を作り 1 回で書き込む」の 1 つ目の Scenario の手順を行い、返ったメッセージを `Update` に渡して `View` から ANSI エスケープを除いて読む
- **THEN** 画面は `L` を押した画面のままで、フッタに `org/app #150 のラベルを更新しました（+docs -wip）` が含まれ、その行の Card の `Labels` は `wip` のまま変わっていない

#### Scenario: 結果が届いても画面を奪わない

- **WHEN** 上の手順で `Enter` を与えた後、コマンドを実行する前に `?` を与えてヘルプ画面に移り、そのうえで結果のメッセージを `Update` に渡して `View` から ANSI エスケープを除いて読む
- **THEN** 画面はヘルプのままで、フッタに `のラベルを更新しました（+docs -wip）` が含まれる

#### Scenario: 書き込みの失敗は赤で出る

- **WHEN** `*gh.Fake` を埋め込んで `EditIssueLabels` だけがエラー `gh issue edit 150 -R org/app --add-label docs: exit 1: HTTP 403` を返す型を `client` にして、`docs` を `[+]` にしてから `Enter` を与え、返ったコマンドを実行して得たメッセージを `Update` に渡し、`View` から ANSI エスケープを除いて読む
- **THEN** フッタに `のラベルを更新できません:` と `HTTP 403` が含まれ、`Cards` は変わらない

#### Scenario: 送信のあと L を押すと印は Cards のラベルのまま

- **WHEN** 1 つ目の Scenario の手順の後に、同じ行で `L` を与えて一覧を開き直す
- **THEN** `docs` の印は `[ ]`、`wip` の印は `[x]` である（`Cards` を書き換えないため、元の集合は最後の取得の時点のままである）
