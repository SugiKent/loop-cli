# session-pane Specification

## Purpose
カード詳細画面と PR 詳細画面の右ペインに、その issue / PR を進めている Claude Code のセッションの稼働状況を出す。取得は 1 回ごとにプロファイルの利用枠を使うので、人が詳細を開いたときと `R` を押したときだけ行う。

## Requirements

### Requirement: 右ペインは紐づくセッションの稼働状況を出す

カード詳細画面と PR 詳細画面の右ペイン（`card-detail`「詳細の本文領域はスクロールし、ヘッダ領域は固定する」が幅を定める）は、上から MUST 次の順で描く。各行は右ペインの幅で切り詰める。右ペインは独立したスクロールを持たず、高さに収まらない分は末尾から落とす。

1. 見出し `Claude セッション`
2. `状態: <状態>`。状態はログの最新の行の種類から決める。`result` なら `終了`、`tool_use` / `tool_result` / `assistant` / `user` なら `実行中`、`env[info]` / `init` なら `起動中`、ログが 0 件なら `不明`
3. `最終更新: <HH:MM>  <経過>`。時刻はログの最新の行の時刻、経過はその時刻から取得時刻までを `m` / `h` / `d` で書いたもの（キュー画面の経過と同じ書き方）
4. セッション ID の行
5. 空行
6. 見出し `直近の動き`
7. ログの行を新しい順に最大 12 行。1 行は `<HH:MM> <種類>` に続けて、種類が `tool_use` なら `<ツール名>: <本文の先頭 1 行>`、`assistant` なら `<本文の先頭 1 行>` を足す。他の種類は種類だけを出す
8. ログに `result` の行があり最終回答を取り出せるときだけ `最終回答: <最終回答>`
9. `取得: <HH:MM>`。取得が走っている間は `取得: 取得中`、まだ 1 度も取得していないときは `R で取得`

セッション情報は詳細の対象と同じく取得した時点のコピーで、GitHub の取得（`auto-refresh` の自動更新、キュー画面の `R`）では MUST 変えない。

#### Scenario: 実行中のセッションが右ペインに出る
- **WHEN** 幅 120・高さ 40 で PR 詳細を開き、`tool_use Bash` の行を最新とするログの取得結果を 12:04 に受け取った状態で `View` から ANSI エスケープを除いて読む
- **THEN** 右ペインに `Claude セッション`、`状態: 実行中`、`最終更新: 12:03  1m`、`直近の動き`、`Bash` を含む行、`取得: 12:04` がこの順で含まれる

#### Scenario: 終了したセッションは最終回答も出る
- **WHEN** 最新の行が `result: success is_error=false turns=110 duration=1168s — CI が緑になりました` であるログの取得結果を受け取った PR 詳細の `View` を読む
- **THEN** 右ペインに `状態: 終了` と `最終回答: CI が緑になりました` が含まれる

#### Scenario: 直近の動きは 12 行までにする
- **WHEN** 200 件のログの行を持つ取得結果を受け取った PR 詳細（高さ 40）の `View` を読む
- **THEN** `直近の動き` の見出しの後に続くログの行はちょうど 12 行で、最も新しい 12 件である

#### Scenario: 取得していない詳細には R で取得と出る
- **WHEN** 幅 120・高さ 40 で PR 詳細を開き、取得結果をまだ受け取っていない状態で `View` を読む
- **THEN** 右ペインに `R で取得` が含まれ、`状態:` の行は含まれない

### Requirement: 出すセッションは PR 本文と issue の routine コメントから決める

`Model` は詳細の対象からセッション ID を MUST 次のとおり決める。

- PR 詳細画面では、選択中の PR の本文に現れる最初の `https://claude.ai/code/session_<ID>` から `session_<ID>` を採る
- カード詳細画面では、`Card.Issue` のコメントを見る。routine のコメント（`<!-- routine -->` またはエスケープされた同じ行で始まるもの）で `session: <ID>` の行を持つものを拾い、**最も新しい 1 件**から `<ID>` を採る。同じ issue に propose と apply の 2 組があれば後の組を採る
- どちらの経路でも見つからないときは、セッション ID が無いものとして扱う（Requirement「取得できない理由は右ペインに出し、画面の他の部分は動き続ける」）

ID は `cse_` で始まる形も `session_` で始まる形もそのまま扱う（`claude-client` がどちらも受け付ける）。

#### Scenario: PR 本文の URL からセッションを決める
- **WHEN** 本文に `https://claude.ai/code/session_01N9YWTYcwFdwhLD38CdASgA` を含む PR の PR 詳細を開く
- **THEN** 右ペインのセッション ID は `session_01N9YWTYcwFdwhLD38CdASgA` である

#### Scenario: issue のコメントは最新の session 行を採る
- **WHEN** `<!-- routine -->` で始まり `session: session_01AAA` を持つコメントと、その後に `session: session_01BBB` を持つコメントがある issue のカード詳細を開く
- **THEN** 右ペインのセッション ID は `session_01BBB` である

#### Scenario: 人のコメントの session 行は採らない
- **WHEN** routine のマーカーを持たないコメントに `session: session_01CCC` と書かれているだけの issue のカード詳細を開く
- **THEN** セッション ID は見つからず、右ペインに `セッション ID が見つかりません` が含まれる

### Requirement: セッションの取得は詳細を開いたときと詳細の R だけで起きる

`Model` はセッションの取得を MUST 次の 2 つの場合にだけ始める。取得は `claude-client` のログ取得を別ゴルーチンで実行するコマンドで行い、30 秒のタイムアウトを付ける。

- **カード詳細画面 / PR 詳細画面に移ったとき**（キュー画面の `Enter`、カード詳細の `Enter` / `g`、PR 詳細の `g`）: 決まったセッション ID の取得結果をまだ持っていないときだけ始める。持っているときは前回の内容と取得時刻をそのまま出し、`claude` を起動しない
- **カード詳細画面 / PR 詳細画面で `R` を押したとき**: 取得結果を持っていても取り直す（`manual-refresh`「R はキュー画面で全件を再取得し、取得中は無視する」の MODIFIED を見る）

次の場合は MUST 始めない。

- 右ペインを出さない幅のとき（1 ペインで描くので出す先が無い）
- セッション ID が見つからないとき、または対象のリポジトリに `claude_config_dir` が無いとき
- 人が `Esc` でカード詳細に戻ったとき、およびヘルプ画面 / URL 一覧画面 / ラベル一覧画面 / 確認画面から詳細に戻ったとき
- キュー画面で人が `R` を押したとき、自動更新（`auto-refresh`）が走ったとき、GitHub の取得が完了したとき、端末サイズが変わったとき

取得の結果はセッション ID ごとに保持し、詳細を閉じても捨てない。保持はプロセスの中だけで、`snapshot-cache` には MUST 書かない。

#### Scenario: 開いたときに 1 回だけ取得する
- **WHEN** 呼ばれた回数を数えるスタブを `claude` の実行経路にして、幅 120 で PR 詳細を開き、取得結果を受け取ってから `Esc` で戻り、もう一度同じ PR 詳細を開く
- **THEN** スタブが呼ばれた回数は 1 回で、2 回目に開いた後の右ペインには 1 回目の取得時刻が出る

#### Scenario: 詳細の R は取り直す
- **WHEN** 上の状態（取得結果を持つ PR 詳細）で `R` を与え、返ったコマンドを実行する
- **THEN** スタブが呼ばれた回数は 2 回になり、右ペインの取得時刻は 2 回目のものに変わる

#### Scenario: キュー画面の R と自動更新では claude を起動しない
- **WHEN** スタブを実行経路にした `Model` のキュー画面で `R` を与えてコマンドを実行し、続いて自動更新の tick を与えてコマンドを実行する
- **THEN** スタブは 1 度も呼ばれない

#### Scenario: 狭い端末では開いても取得しない
- **WHEN** 幅 80 で PR 詳細を開く
- **THEN** スタブは呼ばれず、`View` は右ペインを持たない全幅 1 ペインである

### Requirement: 取得できない理由は右ペインに出し、画面の他の部分は動き続ける

取得ができない、または失敗したとき、`Model` は右ペインの最後の行に MUST 理由を出す。前回の取得結果を持っているときは、その内容を出したうえで理由の行を足す（持っていないときは見出しと理由の行だけを出す）。どの場合も `Cards`・最終更新時刻・詳細の対象・左ペインの内容は MUST 変えず、キュー画面と他のキーは動き続ける。

| 場合 | 出す行 |
| --- | --- |
| 対象のリポジトリに `claude_config_dir` が無い | `claude_config_dir が未設定です` |
| セッション ID が見つからない | `セッション ID が見つかりません` |
| `claude` が PATH に無い | `claude が見つかりません` |
| プロファイルが未ログイン | `未ログインです` |
| `HTTP 404` が返った | `HTTP 404 プロファイルが違う可能性があります` |
| 週の利用上限に達している | `制限中 <解除の時刻>` |
| 30 秒で打ち切った | `30 秒で打ち切りました` |
| 上のどれでもない失敗 | エラーの文字列 |

#### Scenario: claude_config_dir が無いリポジトリ
- **WHEN** `claude_config_dir` を持たないリポジトリの PR の詳細を幅 120 で開き、`View` から ANSI エスケープを除いて読む
- **THEN** 右ペインに `claude_config_dir が未設定です` が含まれ、`claude` のスタブは呼ばれず、左ペインの PR のタイトル行とフッタは今までどおり出る

#### Scenario: 404 はプロファイル違いの疑いとして出る
- **WHEN** `HTTP 404` を返すスタブで PR 詳細を開き、取得の結果を受け取って `View` を読む
- **THEN** 右ペインに `HTTP 404` と `プロファイルが違う可能性があります` が含まれる

#### Scenario: 制限中は前回の内容を残して出す
- **WHEN** 1 度取得に成功した PR 詳細で `R` を与え、週の利用上限のエラー（解除の時刻 `Sep 14 at 2am (Asia/Tokyo)`）を受け取って `View` を読む
- **THEN** 右ペインに前回の `状態:` の行と `最終更新:` の行が残ったまま、`制限中` と `Sep 14 at 2am (Asia/Tokyo)` が含まれる

#### Scenario: 取得の失敗でも他のキーは動く
- **WHEN** 取得が失敗した PR 詳細で `Esc` を与えてキュー画面に戻り、`j` を与える
- **THEN** 画面はキューで選択行が 1 つ下に動き、`Cards` は変わらない

### Requirement: 同じプロファイルの claude は同時 1 本に限り、制限中は起動しない

`Model` は MUST 次のとおり `claude` の起動を抑える。

- 同じプロファイル（同じ `claude_config_dir`）の取得が走っている間は、そのプロファイルの新しい取得を始めない。取得中に `R` を押しても 2 本目は起動しない（キュー画面の `R` が取得中の `R` を無視するのと同じ扱い）。別のプロファイルの取得は同時に走ってよい
- 週の利用上限のエラーを受け取ったプロファイルは、そのプロセスが動いている間は取得を始めない。`R` を押しても起動せず、右ペインに `制限中` と解除の時刻を出す（解除の時刻の文字列は年を含まない表示用の書式なので、時刻として解釈せずそのまま出す）

#### Scenario: 取得中の R は 2 本目を起動しない
- **WHEN** PR 詳細を開いて取得を始めた直後（結果を受け取る前）に `R` を与える
- **THEN** コマンドは返らず、スタブが呼ばれた回数は 1 回のままである

#### Scenario: 制限中のプロファイルは R でも起動しない
- **WHEN** 週の利用上限のエラーを受け取った後、同じプロファイルのリポジトリの詳細で `R` を与え、別の詳細を開き直す
- **THEN** どちらでもコマンドは返らず、スタブが呼ばれた回数は増えず、右ペインに `制限中` が出続ける

#### Scenario: 別のプロファイルは制限中でも取得できる
- **WHEN** 片方のプロファイルが制限中になった後、別の `claude_config_dir` を持つリポジトリの PR 詳細を開く
- **THEN** 取得のコマンドが返り、スタブが呼ばれた回数が 1 つ増える
